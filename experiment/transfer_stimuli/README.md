# transfer_stimuli/ — 転写検証実験の聴覚刺激（打ち切り済みWAV）

**中身は 2026-08-20 に入った**（68かな × 8本 = 544本）。すべて
`experiment/tools/build_transfer_gates.py` が作ったもので、**手で置いたり編集したりしない**。
作り直すときはスクリプトを走らせ直す（下記「作り方」）。

音源は録音した自然音声の採用テイク（`recordings_raw/adopted/`。生の録音はリポジトリに入れない）。
ここに置いてあるのは**実験で参加者に配信する打ち切り済みのWAVだけ**なので、コミットしてよい。

## 置かれるもの

```
experiment/
├── transfer_stimuli/
│   ├── あ_g0020.wav      ← 「あ」を音の実体の開始から 20ms で打ち切ったもの
│   ├── あ_g0040.wav
│   ├── …                  （68かな × 打ち切り7時点）
│   └── あ_full.wav        ← 打ち切りなし（練習・確認問題・音量確認に使う）
└── transfer_audio_manifest.json   ← 索引。実験ページはこれを見てファイルを引く
```

- 68かな = 回答に使うかな表（`transfer_config.js` の `answer_grid`）の全部。
  ターゲット8字だけでなく**まぎれ字60字も同じ規則で作る**（「8字しか出ない」と
  気づかれないように混ぜるため。計画書 4.3）。まぎれ字の全長も要る
  （音量確認で「あ・い・う・え・お」を全長で鳴らすため）。
- 打ち切り7時点は 20・40・60・80・110・150・220 ミリ秒（暫定。A2 で確定）。
- `--salt` を付けて作ると、ファイル名は `sha256(合言葉|かな|時点)` の先頭20桁になる
  （URLからは中身が分からなくなる。索引は実験ページが読むので動作は変わらない）。
  いまは付けていない。視覚課題の画像（`experiment/base/<かな>.png`）が最初から
  そのままのファイル名で、索引も「かな→ファイル」の対応を公開している以上、
  ファイル名を伏せても答えは隠れないため。

## 1本のWAVの中身

```
        ┌ 前置き 50ms ┐┌────── 打ち切り t ms ──────┐
   ─────┤   静けさ    ││   音の中身                 │
        └─────────────┘└───────────────────┬───────┘
        ↑ ファイルの先頭   ↑ 0ms = 音の実体の開始    └ 終端5msは余弦フェードで0へ
                            (acoustic onset)
```

- **0ms は acoustic onset**（音の実体が始まる点）。t ミリ秒の刺激は onset から t ミリ秒ぶん。
- **前置き 50ms**: onset の手前に、録音の静かな区間を残してある。ねらいは2つ。
  (1) 全字で「鳴り出す前の静けさ」の長さをそろえる。「に」は頭に息継ぎを 316ms 巻き込んで
  いたが（`project/録音QC_20260820.md` §10-2）、ここで切り揃えたので落ちている。
  (2) 波形の途中から鳴らすと出る「プツッ」という音を防ぐ。
  録音の余白が 50ms に足りない字は、あるだけ付けてある（実際は 43〜50ms。索引の
  `lead_ms` に1本ずつ入っている）。前置きは onset より前なので**刺激の長さには数えない**。
- **終端は t で終わる 5ms の余弦フェードアウト**。t より後ろの音は1サンプルも入っていない。
- 先頭にはフェードをかけない（音の立ち上がりを守るため）。
- モノラル・16bit・48kHz。ファイル全長 `dur_ms` ＝ `lead_ms` ＋ `gate_ms`。

## 作り方

```bash
# 本番: 採用テイクと、話者本人が全数確認した onset の表を渡す
python3 experiment/tools/build_transfer_gates.py \
    --src recordings_raw/adopted --onsets recordings_raw/adopted_onsets.json

# 動作確認: 既存の合成音で通す（onset は自動検出）
python3 experiment/tools/build_transfer_gates.py \
    --src audio_base_Kyoko --onsets auto \
    --out-dir /tmp/transfer_stimuli_test --manifest /tmp/transfer_audio_manifest_test.json
```

打ち切り時刻の表（字ごと）は `experiment/transfer_config.js` の `audio.gates_ms` にある。
スクリプトは node 経由でその設定を直接読むので、表を2か所に書かなくてよい。

作り直したら必ず一式検査を通す（掲載前チェックリスト D-1）:

```bash
node experiment/tools/check_transfer_stimuli.js
```

## 音源に求めること（計画書 4.4）

1. 日本語を母語とする話者1名が、かなを1字ずつ単独で自然に発話。全68かな。
2. テイクの選び方は録音前に固定（読み間違い・雑音・音割れを除き、長さが真ん中の回）。
3. 音量合わせは1音まるごとに一定の倍率を掛けるだけ（中身の強弱の配分は変えない）。
   加えて電源ハム除去の 100Hz ハイパスフィルタを全字共通で掛ける。
4. **音の実体が始まる点（acoustic onset）を測って記録し、実験の 0ms とする。**
   自動検出（短い窓の実効値が背景雑音を十分超えた最初の点）を初期値に、全数を確認する。
   今回の値は `recordings_raw/adopted_onsets.json`（話者本人が耳で全数確認済み）。
5. 打ち切りは、t で終わる 5ms の余弦フェードアウト（t より後ろの音は一切含まない）。
6. 配信は WAV のまま（音の頭の立ち上がりを守るため圧縮しない）。

## onset の表（`--onsets` に渡す JSON）の形

次のどれでもよい。(a) が今回使っている形。

```json
(a) {"meta": {...}, "adopted": [{"kana": "あ", "file": "adopted/00_あ.wav", "onset_ms": 49.0}, ...]}
(b) {"あ": 50, "か": 42}
(c) {"あ": {"acoustic_onset_ms": 50}, "か": {"acoustic_onset_ms": 42}}
```

(a) は音源のファイル名も一緒に持つので、通し番号付きのファイル名（`00_あ.wav`）のままで使える。
(b)(c) は `<かな>.wav` という名前でディレクトリに並んでいる前提。見本は
`transfer_onsets.sample.json`。

`--onsets auto` で走らせると、自動検出した値を `experiment/transfer_onsets.json` に
書き出す。**本番ではこれを目視確認して直したものを `--onsets` で渡し直す。**
時間の位置そのものがこの実験の独立変数なので、5ms のずれも無視できない（計画書 Q9）。

## 本番刺激が無いときの代用（いまは無効）

索引 `transfer_audio_manifest.json` が読めないとき、実験ページは
`experiment/audio_base/<かな>.mp3`（既存の合成音）を、同じ規則（onset 起点・終端5msフェード）で
ブラウザ側で切って鳴らす**代用モード**で動くようになっていた。画面下に「音声は代用モード」と出る。

本番の刺激が揃ったので、`transfer_config.js` の `audio.fallback.enabled` は **`false`** にした。
索引が読めないときは代用の合成音で静かに走り続けるより、その場で止まったほうが安全
（気づかずに別の音でデータを取ってしまう事故を防ぐ）。合成音で試したいときだけ一時的に
`true` に戻す。**本番データを取る前に必ず `false` に戻すこと。**
