## 本番URL(デプロイ後)

このリポジトリは GitHub Pages で配信され、独自ドメイン **https://unryu.org/iFont/** が正式な配信先である。
`https://qurihara.github.io/iFont/...` でもアクセスできるが、301で `http://unryu.org/iFont/...` へ転送される。
**参加者に案内するURLは、転送をはさまず暗号化された `https://unryu.org/iFont/...` の形にすること。**
以下の `<base>` は `https://unryu.org/iFont` を指す。

乙課題(較正・干渉ゲート)

- 聴覚乙: `<base>/experiment/pilot_soa_audio.html?prod=1&wid=<作業者ID>`
- 視覚乙: `<base>/experiment/pilot_soa_visual2.html?prod=1&wid=<作業者ID>`

frac課題(本計測)

- 聴覚1文字: `<base>/experiment/audio1char.html?prod=1&wid=<作業者ID>`
- 聴覚2文字: `<base>/experiment/audio2char.html?prod=1&wid=<作業者ID>`
- 視覚1文字: `<base>/experiment/visual1char.html?prod=1&wid=<作業者ID>`
- 視覚2文字: `<base>/experiment/visual2char.html?prod=1&wid=<作業者ID>`

`wid`(または `worker_id`)は各プラットフォームが受け渡す作業者IDのパラメータに合わせる。
点検モード(`?check=1`)や候補プール(`?pool=`)は本番モードと排他(点検が優先。聴覚乙のみ)。

### 研究者のパイロット用のURLパラメータ(視覚frac課題)

本番の参加者には付けない。水準を固定して挙動を確かめたいときだけ使う。

- 視覚1文字 `?charms=` : 提示速度(1文字にかける時間、ミリ秒)の水準を上書きする。
  既定は `200,133` の2水準。`?charms=200` とすれば 200 ミリ秒だけの1水準に固定できる。
  **1水準に固定したときは総試行数が 200 問に減る**(本番の 320 問では1本が長すぎて
  試しにくいため)。所要時間の表示も試行数に比例して変わる。
- 視覚2文字 `?overlap=` : 先行文字の残存の条件を上書きする。既定は `none,decay` の2水準。
  `?overlap=decay` とすれば残存条件だけの1水準に固定できる。
  **1水準に固定したときは総試行数が 200 問に減る**(本番の 400 問では1本が長すぎて
  試しにくいため)。所要時間の表示も試行数に比例して変わる。
- 視覚2文字 `?tau=` : C1 の減衰の時定数(ミリ秒)を上書きする。既定は 100。
  例 `?tau=150`。**既定値の 100 は仮の値であり、文献にもとづいて確定する必要がある。**

## セットアップ(一度だけ)

1. **Googleスプレッドシートを作る**。URLからシートIDを控える。
2. スプレッドシートの「拡張機能 → Apps Script」に `gas/code.gs` を貼る。
3. 「プロジェクトの設定 → スクリプト プロパティ」に登録:
   - `SPREADSHEET_ID` = 上のシートID
   - `ANSWER_KEY` = `experiment/answer_key_merged.json` の全文
     (乙課題は正答をクライアントが送るため必須ではないが、frac課題の採点には必須)
4. 「デプロイ → 新しいデプロイ → ウェブアプリ」:
   - 実行者: 自分 / アクセスできるユーザー: 全員
   - 発行された `/exec` URL を控える。
5. `experiment/prod_common.js` の `const SUBMIT_URL = ""` にその `/exec` URL を貼る。
   (空のままだと本番モードの画面は出るが送信はスキップする。ローカル確認用。)
   送信先は6本すべてでここに一本化してある。各課題のJSに送信先は無い。
6. コミットして GitHub Pages に反映。

## 保存されるデータ

シートのヘッダ行は、GAS がシートを**新規作成するときだけ**書き込む。
すでに `trials` / `soa_trials` / `soa_sessions` があるシートに対しては列が増えても
ヘッダは更新されないので、**列を追加した今回は、新しいシートで始めるか、
ヘッダ行を手で追記すること**。

- `soa_trials` シート(乙課題): 1試行1行。
  `ts, participant_id, worker_id, completion_code, task, trial_index, version, speaker, pitch,
  S, c1, c2, c3, resp1, resp2, correct1, correct2,`
  **`actual_soa1, actual_soa2, actual_dur3, ua, dpr, screen, touch, refresh_hz`**(今回追加)
- `soa_sessions` シート(乙課題): セッション完了1行。従来の集計値に加えて
  **`ua, dpr, screen, touch, refresh_hz`**(今回追加)。
- `trials` シート(frac課題): 1試行1行。従来の列に加えて
  **`actual_ms, actual_frames, ua, dpr, screen, touch, refresh_hz`**(2026-08 に追加)、
  さらに末尾に **`char_ms, overlap, tau_ms`**(実験要因の追加にともない末尾に追加)。

### 追加した列の意味

- `actual_soa1 / actual_soa2 / actual_dur3`(視覚乙課題): requestAnimationFrame の実時刻から
  測った、実際の文字の間隔と3文字目の表示時間。名目値 S との差を見るためのもの。
  聴覚乙課題では空欄(Web Audio がサンプル精度で鳴らすため)。
- `actual_ms / actual_frames`(視覚frac課題): 名目の提示時間は `CHAR_MS * frac / 100` だが、
  実際には画面のリフレッシュ周期に量子化される。ターゲット文字を最初に描画したフレームから
  消去したフレームまでの実時間と、実際に描画したフレーム数を記録する。
  frac=0 の試行は一度も描画しないので 0ms・0フレームになる。聴覚frac課題では空欄。
- `ua / dpr / screen / touch / refresh_hz`: 端末環境。各ページが測って
  `PROD.setEnv()` で登録し、`prod_common.js` が送信本文に自動で載せる。
  `refresh_hz` は読み込み直後に40フレームぶん測った推定値。
- `rt_ms`(frac課題): 「刺激の提示が始まってから回答するまで」の時間。
  クリック開始(自己ペース)にしたため、開始ボタンを押すまでの待ち時間は含まない。
- `char_ms`(視覚1文字課題): その試行の提示速度。1文字にかける時間(ミリ秒)で 200 か 133。
  実際の露光時間は `frac × char_ms / 100` になる。他の課題では空欄。
- `overlap`(視覚2文字課題): 先行文字の残存の条件。`none`(統制)か `decay`(残存)。
  他の課題では空欄。
- `tau_ms`(視覚2文字課題): C1 の不透明度の減衰の時定数(ミリ秒)。
  統制条件(`none`)では減衰そのものが無いので空欄になる。他の課題でも空欄。

## 視覚課題に加えた2つの実験要因(2026-08)

### 提示速度(視覚1文字課題)

1文字にかける時間 `CHAR_MS` を 200 ミリ秒に固定していたのをやめ、
**200 ミリ秒と 133 ミリ秒の2水準**にして参加者内で両方を実施する。

- 200 ミリ秒は毎秒 5.0 モーラに相当する。日本語能力試験 N5 の聴解音声(毎秒 5.05 モーラ)と
  ほぼ同じで、最も配慮された遅い読み上げ速度である。聴覚課題の刺激プールがこの速度で
  作られているため、聴覚と視覚を対応づけるときの基準点になる。
- 133 ミリ秒は毎秒 7.5 モーラに相当し、アナウンサーの標準的な読み上げ速度に当たる。
- `frac` は「提示アルゴリズムがどこまで進んだか」を表す無次元の量であり、実際の露光時間は
  `frac × CHAR_MS` である。したがって速度水準を変えても frac のグリッド(0 から 100 まで
  5刻みの21水準)はそのまま使える。
- 出題の配り方: 速度2水準 × frac21水準が均等になるように配る。
  **総試行数は 200 から 320 に増やし、速度水準ごとに 160 試行ずつ**にした。
  統制試行(frac=100)は全体の 5% で、速度水準ごとに 8 問(合計 16 問)。
  段階つき試行 304 問が 42 セル(2水準 × 21水準)に 7〜8 問ずつ入る。
  文字とアルゴリズムは従来どおり全体で均等に配る(文字は各4〜5回)。
  所要時間は約25分。
- **試行数を増やした理由**: 精度目標は「字ごとに約88観測」であり、これは字ごとの推定の
  標準誤差を約5.4ポイントに収めるための値で、干渉判定のマージン δ=8ポイントを
  正当化する根拠になっている。総試行数を据え置いて水準で割ると観測数が半減し、
  標準誤差が約7.6ポイントに悪化して δ の正当化が成り立たなくなる。
  そのため水準ごとに従来と同じ 160 試行を確保した。

### 先行文字の残存(視覚2文字課題)

C1(1文字目)を 0.2 秒まるごと提示したあと C2(2文字目)を同じ枠に出し、frac% の時点で
打ち切って **C2 が何の字だったかを答えさせる** 課題に、提示方式の要因を2水準で加えた。

- **`none`(統制・従来どおり)**: C1 が消えてから C2 が出る。
- **`decay`(先行文字の残存)**: C2 の提示中も C1 が薄くなりながら同じ枠に重なって残る。
  C1 の不透明度は、C2 の提示が始まった時刻を起点として `alpha = exp(-t / TAU_MS)` の
  指数減衰にする。描画は既存の提示アルゴリズムをそのまま使い、まず C1 を最終状態
  (完全に現れた状態)でその不透明度で描き、その上に C2 を frac の進み具合で重ねる。
  重ねるときは乗算合成にしてある(単純に上書きすると C2 の白い背景が C1 を消してしまうため)。
- **`TAU_MS = 100` は仮の値である。** 文献にもとづいて確定するまでの暫定値であり、
  `visual2char.js` の1箇所で定義してある。`?tau=` で上書きして試せる。
- **設計上の要**: この条件で増えるのは C1 の可視時間だけで、**C2 の可視時間は一切変わらない**。
  回答対象が C2 なので、「長く見せただけ」という交絡が生じない。
  C2 の提示開始時刻と打ち切り時刻は両条件で完全に同一でなければならず、この性質を
  壊す変更を加えてはならない。
- 出題の配り方: 条件2水準 × frac21水準が均等になるように配る。
  **総試行数は 200 から 400 に増やし、条件ごとに 200 試行ずつ**にした。
  統制試行(frac=100)は全体の 5% で、条件ごとに 10 問(合計 20 問)。
  段階つき試行 380 問が 42 セル(2水準 × 21水準)に 9〜10 問ずつ入る。
  C2 の文字は各5〜6回。所要時間は約26分。
  試行数を増やした理由は視覚1文字課題と同じ(水準ごとに従来と同じ観測数を確保するため)。
- 教示に「1文字目が薄く残ったまま2文字目が重なって見えることがある。故障ではない」という
  説明を1文加えてある(参加者が不具合と誤解しないため)。

## frac課題に入れた「乙式改善」(2026-08)

乙課題で先に導入した参加者体験を、frac課題4本にも移した。

1. **クリック開始(自己ペース)**: 刺激は自動で始まらない。
   「準備ができたら開始（またはスペースキー）」を押してから提示・再生する。
   押すまで50音の回答ボタンは押せない(提示前に答えてしまうのを防ぐため)。
   押したあとは同じボタンが「もう一度みる／きく」に変わり、従来どおり何度でも見直せる。
2. **教示と練習のフィードバック**: 何を答えるのか・**難しくて当然**であること・
   **勘で答えてよい**ことを、教示と練習の各問のあとの画面で繰り返し伝える。
   視覚課題は練習で正解も表示する。聴覚課題は正解表(answer_key)が端末に無いため
   正解は表示できず、参加者自身の答えと注意書きだけを見せる。
3. **出題の配り方**: 水準ごとに均等な試行数を割り当ててから順序を混ぜる方式にした。
   この時点では総試行数は各課題 200 問だった(練習5問は別)。
   - frac 水準: 統制試行(frac=100)を 5%(10問)確保し、残り190問を21水準に均等配分(各9〜10問)。
   - 文字: 視覚課題は78字を均等配分(各2〜3回)。聴覚1文字課題は刺激プールが68音1対1なので
     刺激を均等配分すれば音も均等になる。
     **聴覚2文字課題だけは文字の均等配分ができない**(manifest に正解を含めない設計のため、
     クライアントがどの文字か知らない)。刺激は5184対からの非復元抽出のまま。
   - 提示アルゴリズム(視覚): fade・blur・moya を均等配分。
   - なお視覚1文字課題と視覚2文字課題は、下記の実験要因を加えたのにともない、
     frac 水準の均等配分を**要因の水準ごとに独立に**行う方式に変え、
     **総試行数も増やした**(視覚1文字 320問・視覚2文字 400問)。統制試行 5% は変わらない。
     詳しくは次の節を見よ。
