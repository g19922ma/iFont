## 1. 手法のしくみ

### 1.1 やりたいこと

かるたでは、読手が読み始めたわずかな音で札が決まる。そのとき頭の中では
**時間が進むにつれて候補が絞られていく**。この過程を**文字の見え方**で作り直す。

**キモは「読みやすく見せる」ことではない。**

> ある時点で音を聞いた人の 55% しか分からないなら、
> その時点の文字表示も **55% の人にしか分からない**のが正しい。

### 1.2 三段構え

```
  ①測る（聴覚）           ②作る                  ③測る（視覚）＋確かめる
  音を途中で打ち切って      A(t) と V(s) から       アニメを進み具合 s で止めて
  識別率 A(t) を測る       s(t)=V⁻¹(A(t)) を作る   V(s(t)) が A(t) に一致するか
```

- **t** ＝ 音の打ち切り時間（ms）
- **s** ＝ アニメーションの進み具合（%）
- **A(t)** ＝ 時間 t まで聞いたときの正答率（68択の強制選択）
- **V(s)** ＝ 進み具合 s まで進めたときの正答率（72択）

### 1.3 4つのアニメーション方式

| 名前 | 何が起きるか | 情報の落とし方 |
|---|---|---|
| うすい→濃い（fade） | 不透明度が上がる | **一様** |
| 点が増える（reveal） | 点描の密度が上がる | **一様** |
| ぼやけ（blur） | ぼかし半径が減る | **空間周波数**（細部が先に消える） |
| 端から（wipe） | 左上から順に現れる | **空間位置**（右下が最後） |

### 2.4 投稿前に取り下げた主張（3件）

**これは他のAIに必ず伝えてほしい。同じ間違いを繰り返さないため。**

| 取り下げ | 実際は |
|---|---|
| 一様な方式は濁点の影響を受けない（−0.3/−1.3pt） | **4方式すべてが 8.6〜15.8pt 低下** |

```
  20試行以上        ρ = 0.40
  対象8字（122試行） ρ = 0.74     ← 典型的な希薄化
```

> **教訓：紛れ字は「学習対策」であって「解析に使えるデータ」ではない。**

### 2.5 いま一番確かな主張

**濁点の不利さは方式によって違う。**交互作用の検定**1本**で確認：

> **端から − うすい→濃い ＝ +6.3pt［95%区間 +2.2, +10.4］、p = 0.0055**

| 方式 | 濁点による低下 | 中点の伸び |
|---|---|---|
| うすい→濃い | +9.5pt | 1.13倍 |
| 点が増える | +13.4pt | 1.25倍 |
| ぼやけ | +15.3pt | 1.19倍 |
| **端から** | **+15.8pt** | **1.82倍** |

濁点は字の**右上**にあるので、左上から出す「端から」では最後に現れる、というのが説明仮説。
**まだ観察であって、実験していない。**

## 3. 決まったこと（2026-08-26）

### 3.1 λ正規化をやめ、生の正答率で転写する

もとは `q = (p−γ)/(λ−γ)` と各刺激の天井で正規化していた。これだと

> **43%しか聞き取れない「ぱ」を、97%読める字に写す**

ことになり、研究の定義（「55%なら55%」）と食い違う。

**決定：`s(t) = V̂⁻¹(Â(t))` を生の正答率のまま行う。**

- γ（1/68）は**曲線推定の下限パラメータとしてだけ**残す。転写時に再正規化しない
- 視覚側の λ は「当てはめ値」と「100%まで出したときの実測」の**大きい方**を使う
  （当てはめλが実測を下回ると逆引きが破綻するため。実際に起きていた）
- 非単調は**当てはめた曲線を使う**ことで回避（保序回帰は不要）

**結果：文字は完成しない。**

| 字 | 聴覚の到達点 | 文字が止まる所 | そこで読める割合 |
|---|---|---|---|
| ま | 90.3% | ぼやけ 67.5% | **90.3%** |
| が | 2.9% | ほぼ 0% | **ほぼ読めないまま** |

「が」がほとんど動かないのは**正しい挙動**（著者確認済み）。

### 3.2 対象字を絞らない

もとは「曲線がきれいな字」を選ぼうとしていた。**その基準は捨てた。**

> **検証すべきは「測った曲線 A(t) を視覚で再現できるか」であって、
> A(t) が正しい聴覚特性かどうかは別の話。**

A(t) は生成に渡す**目標**として与えられているだけで、群Bは同じ A(t) と突き合わせる。
したがって「が」が刺激不良かもしれないことも、γが字ごとに違うことも、
非単調なことも、**転写の検証には効かない**。

**決定：8字すべてでやる。**

## 4. 較正データから分かった「転写の限界」

**これが今回いちばん面白い発見だと考えている。**

### 4.1 飛び幅は方式ではなく音の側で決まる

提案条件は定義上その時点の音と同じ正答率を出す。したがって
**1コマの間に理解度が何ポイント飛ぶかは、聴覚の曲線だけで決まる。**

参加者の画面の実測：**中央値 58Hz（1コマ17.2ms）、範囲 4〜198Hz**。

| 字 | 1コマの飛び（8方式すべてほぼ同じ） |
|---|---|
| つ | 18pt |
| か | 22pt |
| ら | 32pt |
| ぱ | 60pt |
| **ま** | **67〜75pt** |
| **あ** | **83〜94pt** |
| が | 0〜2pt（そもそも動かない） |

**当てはめの副産物ではない。生データで確かめられる：**

```
  あ  10ms →  0.0% ／ 20ms → 75.8%     10ms で 76pt 上がる
  ま  35ms →  3.0% ／ 50ms → 73.5%     15ms で 71pt 上がる
  か  10ms → 12.1% ／ 85ms → 97.1%     75ms かけて上がる
```

> **音声の識別は、画面の書き換えより速く進むことがある。**
> その場合、進み方をどう変形しても、どの方式を使っても、途中を描けない。

### 4.2 天井が低い字ほど再現しやすい（反直感）

| 字 | 聴覚の天井 | 上がり幅 | 1コマの飛び |
|---|---|---|---|
| し | 0.27 | 27pt | **13pt** |
| ら | 0.42 | 42pt | 26pt |
| あ | 0.96 | 96pt | **86pt** |

**「し」は最大でも27ポイントしか上がらないので、一気に上がっても27ポイント。**

> **聴覚で分かりにくい字ほど、視覚で再現しやすい。**

### 4.3 方式によって「環境のずれへの強さ」が25倍違う

進み具合が1%ずれたときの正答率のずれ（参加者ブートストラップ300回）：

| 方式 | 点推定 | 95%区間 |
|---|---|---|
| **ぼやけ** | **1.4pt** | [1.2, 2.3] |
| 点が増える | 16.6pt | [12.4, 21.4] |
| 端から | 32.9pt | [10.3, 203.4] |
| うすい→濃い | 34.4pt | [20.8, 61.7] |

理由：**うすい→濃い と 点が増える は全変化が 0〜5% に詰まっている**。
V(s) の緩やかさ σ は、うすい→濃いが **0.5%** に対し ぼやけは **10〜14%**。
**うすい→濃いは「見えるか見えないか」の閾値そのもの。**

実測でスマホとPCで ぼやけの中点が **32.4% と 51.2%** ずれていたので、
この脆さは実際に効く可能性がある。

### 4.4 RQ4（速さの影響）は半分しか片づいていない

**もともとの問い：識別率は進み具合 s だけで決まるのか、そこへ至る速さにも左右されるのか。**
これは**手法の土台そのもの**（時間軸を伸び縮みさせて写す以上、s だけで決まる必要がある）。

較正で 300ms / 500ms の2水準を仕込んだが、**画面の書き換え粒度のせいで
4方式中3方式は「同じ絵しか出ていない」**（薄い水準では両方とも描画2枚）。

| 方式 | 8水準中、実際に絵が違った数 |
|---|---|
| **ぼやけ** | **8（全部）** |
| 端から | 5 |
| うすい→濃い | 3 |
| 点が増える | 3 |

- **ぼやけ全体：−2.3pt [−8.4, +3.8] → 効果なし**（土台を支持）
- 19セルにHolm補正 → **「点が増える」4% だけ +20.7pt が残る**（p=0.0005）

この1セルは説明がついていない：
終点の絵は**完全に同一**（両方4.000%、全件が終点描画）、参加者の偏りもなし
（全体の出来の差 −1.2pt）。違いは**描画2枚 vs 3枚**、部分的な絵が**17ms長く見えた**だけ。
一方 ぼやけ48% は **+100ms 長くても効果ゼロ**。

> **うすい→濃い と 点が増える では「s だけで決まる」が未検証で、反例が1つある。**
> しかもこの2方式の持ち場（0〜5%）は、まさに描画2〜3枚の領域。

## 5. やろうとしている実験

**⚠ 重要な方針（著者の判断）：**
> **予測で却下されたものも実験に含める。**
> 除いてしまうと、予測が当たっていたかを永久に確かめられない。
> **是か非かの線引きは人間が決めることで、解析で先に決めない。**

### 実験①：群B（転写の検証）— もとの計画の本体

| | |
|---|---|
| 問い | **RQ1**：生成したアニメを初見の集団に見せて、A(t) が再現されるか |
| 対象 | **8字 × 4方式**（絞らない） |
| 条件 | 提案 ／ 等速 ／ 開始と速さだけ合わせた直線（s=at+b） |
| 主判定 | 目標曲線との**距離E**。仮説1「提案>等速」、仮説2「提案>直線合わせ」 |
| 規模 | 8字 × 8条件 × 7点 = 448セル。1人24問（約6分）。**1セル15試行なら560人** |
| 実装 | **ページ・ロジックは既存。warp表は生成済み** |
| 状態 | **条件を確定すれば回せる** |

**懸念：**「あ」「ま」は提案条件も等速条件もどちらも階段になるので、
「階段 vs 坂」を比べるだけになる可能性。**それ自体が 4.1 の実証にはなる。**

### 実験②：wipe の向きを反転する（機構の検証）

| | |
|---|---|
| 問い | 濁点の不利さは**空間的な位置**のせいか |
| 設計 | 「端から」だけを、**左上から（ltr）と右上から（rtl）の両方**で測る |
| 主仮説 | **「濁点の有無 × 向き」の交互作用 1本だけ** |
| 対象 | 較正と同じ8字（＋紛れ字） |
| 規模 | **120人**でシミュレーション上100%（効果が完全に消える場合）、86%（半分の場合） |
| 状態 | **決定待ちなし。すぐ回せる。** |

**実装済み：**`transfer.js` v3.16 で向きが試行ごとに変えられる。
1人が8字中4字をltr、4字をrtlで見る。40人ぶんで各字が **ltr 20 / rtl 20** ちょうど。
乱数は使わず参加者の連番から決定的に決まる。

**水準を並べ直した：**較正の並び `0.5/1/2/4/8/14/25/100` は**25%の次が100%**で
その間が空白だった。ところが実測では

```
   25% … 清音 44.1% / 濁点あり  0.0%     ← 大きく開いたまま
  100% … 清音 96.8% / 濁点あり 97.6%     ← 次の点でいきなり合流
```

**どこで濁点が読めるようになるかを一度も測っていない。**
そこで `2/8/20/35/50/65/80/100` に変更（このフェーズのみ）。

**副産物：**1方式に絞るので紛れ字のデータが4倍濃くなり、
**濁点の字が2字（が・ぱ）ではなく25字ぶん**取れる。

### 実験③：速さの追試（土台の検証）

| | |
|---|---|
| 問い | うすい→濃い・点が増える で「s だけで決まる」が成り立つか |
| 設計 | 薄い水準（0〜5%）に絞り、**フレーム数が確実に違う**速さ2水準（例 300ms vs 1500ms） |
| 規模 | 8字 × 2方式 × 薄い水準4つ × 速さ2 = 128セル。**160人・約6千円** |
| 状態 | 未実装（水準設計が要る） |

### 実験④：8字 × 8方式の選別実験（**次の論文向け**）

**単独4方式＋組み合わせ4方式**（一様 × 空間の総当たり）で、
**理解度と快適度の両方**を測り、「どのマスがなぜ却下されるか」の表を作る。

| パート | セル／マス | 1人 | 人数 |
|---|---|---|---|
| 識別（理解度） | 512 | 24問・6分 | 320人 |
| 快適度 | 64 | 8マス・3分 | 120人 |

**⚠ 別集団に分ける。**識別を先にやると字を覚えてしまい、
「見やすさ」が「もう知っている字だから見やすい」に化けるため。

**組み合わせの作り方（重要な設計判断）：**
同じ進み具合を両方に入れると**遅い方に飲み込まれる**
（うすい→濃いは0〜3.65%で終わり、ぼやけは0〜91.96%かかる。持ち場が25倍違う）。
そこで**それぞれの働く区間へ進み具合を割り当て直す**。

**組み合わせの V(s) は未測定**なので、
**「2つの劣化が独立に効く」= q = q₁ × q₂ という予測**を立てた。
**この予測が当たるかどうかが検証対象になる。** 外れたら「独立ではない」という知見。

**⚠ 一番重い作業は「組み合わせ方式の水準の並び」の設計。**
単独4方式は専用ツール（`level_chooser.html`）で試行錯誤して決めた経緯がある。
ここを見誤ると較正のときと同じで、薄い水準に全部詰まって何も測れない。

**WISS 2026 には間に合わない見込み。次の論文の設計として残す。**
