## 1. 背景とリサーチクエスチョン

### 1.1 経緯（要約）

iFontの狙いは、音声を聞くのと「同じ時点に同じだけ分かる」文字表示を作ること
（かるたの決まり字体験を、聴覚に頼れない人にも字幕で届けたい）。当初は68かな全部の
較正データを大規模実験で先に測る計画だったが、文献調査の結果、測定法自体は標準的
（ゲーティング法、1961年〜）で、聴覚と視覚の曲線を測って**比べる**ことまで先行研究がある
（Sánchez-García et al. 2018）と判明。一方、**測った音声の曲線から視覚アニメーションを
生成し、識別の時間経過が再現されるかを独立参加者で検証した研究は、調査の範囲では
見当たらない**。そこでまず8文字の小規模構成でそれを検証する（近傍研究との区別 → Q11）。

### 1.2 リサーチクエスチョン

**音声で測定した「分かっていく過程」を、文字アニメーションの時間軸の変形（time-warp）で
再現できるか。**

例: 「た」の音声を先頭から少しずつ長く聞かせて「いつ何％の人が当てられるか」の曲線
（target curve）を測る。文字「た」のフェードインの進み方をこの曲線に合わせて設計したとき、
**初見の別の人が、音声と同じ時間経過で「た」と分かるようになるか**を確かめる。
（「別の人」にする理由と「再現」の意味 → Q1）

### 1.3 iFontの概念との対応

| 概念整理での言葉 | 本実験での姿 |
|---|---|
| Perceptual Score（識別過程の中間表現） | 音声の識別曲線 A_i(t)。1文字なので対象＝かなそのもの（→ Q2） |
| 変換g（聴覚と視覚を同一の認識率で対応づける較正） | time-warp s_i(t)=V_i⁻¹(A_i(t))。gを時間軸に沿って適用したもの |
| frac課題（gの実測） | 群A・群A′のゲーティング課題 |
| 文字合成（スコアを動的な文字として実現する処理） | 生成アルゴリズム（3.1） |
| iFont（文字合成の出力） | 生成されたアニメーション（群BのProposed条件） |

本実験＝**文字合成が本当に成立するか**（同一スコアの共有で「同じ時点に同じだけ分かる」が
実現されるか）の最小構成での検証。

## 2. 検証したい仮説

群Bに、作り方の違う3種類のアニメーション（3.2）を見せ、それぞれの識別曲線が
音声の曲線（target）にどれだけ近いかを競わせる。「近さ」の定義は6.2。
実験後に支持/不支持を明記する。

- **仮説1（転写は効く）**: iFont は、等速の普通のフェードイン（Baseline 1）より target に近い。
- **仮説2（速さ合わせでは足りない）**: iFont は、速さだけ音声に合わせたフェードイン
  （Baseline 2）よりも target に近い。
  - 不支持なら「速さを合わせるだけで十分」が結論。それも設計知見として報告する。

操作チェック: 確認A＝全長提示の確認問題の正答率が十分高い。確認B＝提示量とともに
正答率が上がる曲線が得られている。

## 3. 実験の構成

### 3.1 全体の流れ（3つの独立群、「測る→作る→確かめる」）

| 段階 | 群 | 課題 | 得るもの |
|---|---|---|---|
| 較正1 | 群A | 音声を先頭から t ms で打ち切り→かな表から回答 | 音声識別曲線 A_i(t)（target） |
| 較正2 | 群A′ | 基準アニメ（線形フェード）を進行度 s% で打ち切り→回答 | 視覚識別曲線 V_i(s) |
| 生成 | — | s_i(t)=V_i⁻¹(A_i(t)) で各文字のアニメを一発生成し**フリーズ** | iFont（人手調整なし） |
| 検証 | 群B | 3条件のアニメを t ms で打ち切り→回答 | 生成物の識別曲線 |

- 3群は互いに独立（重複参加を排除。理由 → Q1）。
- フリーズ: 生成アルゴリズム・パラメータ・全8字の s_i(t) を群B取得**前に**コミット固定し、
  ハッシュを記録。群Bの結果を見てからの再調整はしない（→ Q3）。
- 基準アニメの長さ・濃度カーブは群A′の前にパイロットで決める設計パラメータ
  （現行200msは旧製品要件由来。選定基準 → Q4）。

### 3.2 群Bの3条件

| 条件 | 内容 | 何に答えるか |
|---|---|---|
| Baseline 1 | 等速の線形フェード | 何も工夫しない場合の基準 |
| Baseline 2 | 50%識別時刻だけtargetに合わせた線形フェード | 「速く/遅くしただけでは？」への直接の答え（→ Q5） |
| Proposed | 曲線全体からの time-warp（＝iFont） | 「分かっていく形」まで再現できるか |

### 3.3 課題の詳細

- **文字**: 8字（暫定）。時間構造の多様性を代表——母音のみ／無声破裂／有声破裂／摩擦／
  鼻音／清濁ペアを含め、QC（3.4）通過字から選定。
- **提示水準**: 文字ごと7時点（暫定）。聴覚は acoustic onset（音の実体の開始点）からの
  絶対ms、視覚は進行度%。**早い側を密に**配置し全長付近まで覆う（時間帯の根拠 → Q6）。
  配置はA2シミュレーションで確定。
- **回答**: 全かな表からの強制選択（1問1答・選び直し確認つき・実験1と同じ画面）。
  当て推量の正答率が聴覚1/68・視覚1/72に定まり、曲線の床γとして使える（→ Q7）。
- **問題数（暫定）**: 群A・A′＝8字×7時点+確認4問≈60問（約6分）。群Bは3条件×56=168問が
  上限のため、実験協力者間で釣り合いよく分担する割付をA2で確定（1人約10分以内）。
- **募集**: Yahoo!クラウドソーシング。日本語母語・18歳以上・各群1人1回・群間重複なし。
  再生機器自由（合図音→0.6秒→刺激で無線の頭欠けを吸収。実験1と同じ）。
- **人数（暫定）**: 各群25人。A1.5シミュレーションで、この規模なら転写の20msの系統ずれを
  偶然ばらつき（SD≈4.8ms）の約4倍として検出できると確認済み。確定はA2。

### 3.4 刺激（音源）

## 4. 何を測定して分析するか

- 主要指標: **正誤**（1問ごと。採点方式は実験1と同じ）。
- 副次指標: 反応時間・聞き直し回数・実測提示時間（視覚は描画フレーム実時刻）・所要時間・
  途中再開回数・セッション順・端末環境。
- 判定はすべて正誤から行う。主観アンケートはシステム評価段階の実験で採用（実験1と同方針）。

## 6. データの分析方法

### 6.1 曲線の当てはめ

文字ごとに心理測定関数 P(t) = γ + (1−γ−λ)·logistic((t−μ)/s) を最尤推定。
γ＝当て推量の床（1/68・1/72に固定）、λ＝lapse（十分見えていても起きる押し間違い率・
自由推定）、μ＝50%識別時刻（中点）、s＝急峻さ。文字はランダム効果とする階層的な扱いを
基本とし、個別文字は探索的に図示。

### 6.2 成功判定（「近さ」の定義）

- **主判定: 中点差**。各条件の中点と target の中点の差。Proposed の |中点差| が
  Baseline 1・2 より小さいか（同じ文字同士のペア比較で文字差を消す）。
- **副判定: 曲線距離E**＝両曲線の評価時点上の平均絶対差（正答率pt）。中点が合っても
  「分かっていく形」が違う場合を検出（ノイズ床 E≈3.7pt、形の不一致は8〜10pt）。
- **報告**: 差と信頼区間、「Baselineよりどれだけ近いか」。等価マージン（±何msなら実質同じ）は
  次の段階で扱う。
- 探索的図示: 文字ごとの転写誤差・天井・混同行列・急峻さ（急峻さを判定に使わない理由 → Q10）。

### 6.3 除外基準

実験1の6.3を踏襲（確認問題の誤答数・無応答・所要時間異常・重複参加）。閾値はA2と同時に固定。

## 付録A: 設計の理由（Q&A）

**Q1. 「別の人で確かめる」って、再現性（追試）の実験ということ？**
違う。較正した本人たちで確かめると「その人たちに合わせ込んだだけ」と区別がつかないため、
生成に関わっていない初見の人（群B）で効果を確かめる。合わせ込み排除の手続きであって、
同じ実験を繰り返す追試の意味ではない。

**Q2. 「対象＝かなそのもの」とは？（F=恒等）**
概念整理では、スコアは「対象（かるたなら歌）がいつ識別できるか」を記述し、それを
「どの文字をいつ提示するか」へ翻訳する橋渡しF（決まり字の組合せ論）を挟む。本実験は
識別する対象がかな1文字そのものなので、この翻訳は何もしない（入力をそのまま返す＝恒等写像）。
概念の特殊ケースにそのまま収まる。

**Q3. なぜフリーズするのか？**
time-warpは十分自由度のある変換なので、「群Bの結果を見て調整を繰り返せばいつかは合う」
という批判が成り立ってしまう。群B取得前にコミットで固定し、一発生成であることを
履歴で証明する。

**Q4. 基準アニメの200msをなぜ見直す？**
200msは旧製品要件（かるた0.2秒/モーラ）の名残で、知覚測定として選んだ値ではない。
測定上重要なのは、V(s)が進行度の全域で緩やかに立ち上がること。フェードが速すぎると
「薄くてもすぐ読める」ためV(s)が狭い範囲で床から天井へ跳び、逆引きV⁻¹が不安定になって
生成の質が落ちる。だからパイロットで長さ・濃度カーブを選んでから較正する。

**Q5. Baseline 2はなぜ要る？**
ProposedがBaseline 1に勝っただけなら「表示を速く/遅くしただけ」で説明がつく。
速度合わせを既にした対照（Baseline 2）に勝って初めて「曲線全体を使う意味がある」と言える。
差がなければ「速度1パラメータで足りる」という明快な知見であり、どちらでも報告する。

**Q6. 打ち切りが40msとか、急すぎない？**
かな1音の識別情報は先頭の数十msに集中している。清濁を分ける主手がかりVOT
（破裂から声帯振動開始までの時間）は日本語で25〜45ms——「た」か「だ」かは最初の40ms以内で
ほぼ決まる。Furui (1986)は識別率がスペクトル変化最大点前後の約10msで急峻に立ち上がることを
示した。全長150〜300msのうち後半の母音定常部は「どの字か」の新情報をほぼ足さない。
「もっと遅く分かるはず」という体感は反応時間（数百ms）が乗っているためで、ゲーティング法は
回答時間を無制限にすることで情報の到達時刻と反応の速さを分離して測る。

**Q7. 8字しか出さないのに、なぜ回答は全かな表？**
選択肢数で当て推量の正答率（床γ）が決まる。全かな表なら1/68・1/72に固定でき、
解析にそのまま使える。また出題範囲を悟らせず、実験1と課題の性質が揃う。

**Q8. テイク選択と音量合わせの決め方はなぜ機械的？**
「都合の良いテイクを選んだ」「音を整えて結果を作った」という批判の余地を消すため、
選択基準（雑音等を除外→長さが中央値に最も近いもの）を録音前に固定する。音量も、
音の頭のノイズ強度自体が清濁の手がかりになり得るため、内部バランスを変えない
一定ゲインのみとする。

**Q9. なぜ時間0をacoustic onsetに固定する？**
ファイル先頭基準にすると、先頭の無音余白のぶん「40ms提示」が実際は音響情報35ms、
といったずれが全文字の曲線に乗り、文字間比較も先行研究との比較も狂う。
onset（音の実体の開始点）を測ってそこを0msと定義する。

**Q11. 「未検証」って本当？似た研究はないの？**
部品はすべて既存: ゲーティング測定（竹内1961・Furui 1986）、聴覚と視覚の曲線の測定・比較
（Sánchez-García et al. 2018）、文字の段階提示（Petersen & Andersen、上月らのdynamic text）、
モダリティ間の知覚対応づけの発想（古典的なcross-modal matching）、音声のタイミングに
合わせた文字表示の工学（カラオケのワイプ。ただし識別率への較正も検証もない）。
見つかっていないのは「測った音声の識別曲線を入力に、較正済みの逆引きでアニメーションを

**Q10. なぜ急峻さ（傾き）を判定に使わない？**
二段階の推定（曲線を推定→逆引きに使用）では傾きが系統的に浅く出るバイアスがあることを
シミュレーション（A1.5）で確認した。バイアスの乗る量を勝敗判定に使うと誤判定のもとに
なるため、判定は中点差と曲線距離Eで行い、急峻さは探索的な図示に回す。
