### 覚えておくこと: 利用許可はデプロイのたびに要ることがある

clasp で作ったスクリプトは、持ち主が一度も許可を与えていないと、そのままでは
スプレッドシートを読み書きできない。`/exec` を開くと `Authorization needed` が出て
HTTP 403 になる。直し方は、ブラウザで `/exec` を開き
**「REVIEW PERMISSIONS」→ アカウント選択 →（未確認アプリの警告が出たら「詳細」→「移動」）
→「許可」**。**これは自動化できない**（本人が画面で押すしかない）。
本番用に新しいデプロイを作ったときは、もう一度必要になる。

### どこに何を書くかの整理（`prod_common.js` を触らない理由）

| 送るもの | 送信先の設定 | 送る場所 |
|---|---|---|
| 転写検証の1問1行・見え心地 | `transfer_config.js` の `logging.submit_url` | `transfer.js` の `sendRecord()` |
| 集団の振り分けの問い合わせ | `transfer_config.js` の `roster.status_url` | `transfer.js` の `resolveAssignment()` |
| 実験1（乙課題・frac課題） | `prod_common.js` の `SUBMIT_URL`（**空のまま**） | `prod_common.js` の `post()` |

`prod_common.js` は実験1と共用なので、そこを埋めると既存の実験の保存先まで動いてしまう。
だから転写検証だけ別の窓口を持たせている。`sendRecord()` は、`prod_common.js` が外に
見せていない3つの値（再生機器の申告・再開回数・中断していた合計秒）を、同意画面の
ラジオボタンと `PROD.loadState()` の戻り値から同じ規則で作り直して封筒に載せている。

### 保存基盤の方針: 最終的には Firestore 一本化

GAS は応答の本体を `script.googleusercontent.com` へリダイレクトして返す作りで、
この経路が**一過性で失敗して HTML を返す**ことがある（2026-08-21 に実機で発生。
サーバ自体は正常だった）。Firestore は REST を直接叩くのでこの中継が無い。
一方で、いま GAS がやっている**採番と重複チェックを作り直す**必要があり、
そこは今日の日程に載らない。そこで段取りを3つに分けた。
