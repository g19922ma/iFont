## B. サーバ側（Google Apps Script）の用意

いま `gas/code.gs` は**まだ転写検証実験に対応していない**。`gas/transfer_patch.md` の
差分を当てる必要がある。既存の実験（乙課題・frac課題）の処理には触らない差分になっている。

- [ ] **B-1 記録用のスプレッドシートを決める**。
      **下見は既存の実験とは別のスプレッドシートを新しく作ることを勧める**（理由は G-1）。
      URLからシートIDを控える。
- [ ] **B-2 Apps Script に `gas/code.gs` を貼る**（スプレッドシートの「拡張機能 → Apps Script」）。
- [ ] **B-3 `gas/transfer_patch.md` の3つの差分を当てる**。
      - 追加1・2: `doPost` の中、`body.kind === "soa_trial" || body.kind === "soa_done"` の分岐の
        すぐ下に、転写検証への振り分け2行を入れる。
      - 追加1・2の本体: `handleTransferTrial` と `handleTransferWellbeing` をファイル末尾に足す。
      - 追加3: `doGet` を差分のものに**置き換える**（`transferStatus` も一緒に足す）。
- [ ] **B-4 スクリプトプロパティを登録する**（「プロジェクトの設定 → スクリプト プロパティ」）。
      - `SPREADSHEET_ID` = B-1 で控えたシートID
      - `ANSWER_KEY` … 転写検証では使わない（採点はブラウザが送る `target_char` で行う）。
        既存の課題も同じデプロイで動かすなら要る。
- [ ] **B-5 デプロイする**。「デプロイ → 新しいデプロイ → ウェブアプリ」。
      - 実行するユーザー: **自分**
      - アクセスできるユーザー: **全員**
      - 発行された `/exec` URL を控える。
      > コードを直したときは「デプロイを管理 → 編集 → バージョン: 新バージョン」で
      > **上げ直さないと反映されない**。URLは同じままなので、直したつもりで古い版が
      > 動き続ける事故が起きやすい。
- [ ] **B-6 `/exec` URL を2か所に貼る**。
      - `experiment/prod_common.js` の `const SUBMIT_URL = "";`（回答の保存先）
      - `experiment/transfer_config.js` の `roster.status_url: ""`（集団の振り分けと重複の照合）
      > `prod_common.js` は既存の実験ページも読んでいる。ここを埋めると既存の課題も
      > 同じ場所へ保存するようになる（同じ `code.gs` なので問題ない）。
- [ ] **B-7 名簿サーバに繋がらないときの動きを決める**。
      `experiment/transfer_config.js` の `roster.require_server` を **`true` にすることを勧める**。
      `false` のままだと、サーバに繋がらないとき参加者IDのハッシュで集団を決めて先へ進むため、
      音声8人/視覚8人の釣り合いが崩れ、重複参加の照合もできない。
      `true` なら繋がらない人はお断り画面で止まる（報酬は発生しない）。
