## 承認・非承認の基準（3つの掲載で共通）

| 判断 | 条件 |
|---|---|
| **承認** | 提出された完了コードが、サーバの**完走レコード**にある |
| **承認（ただしデータは分析から外す）** | 完走レコードはあるが、回答の質が低い（打ち切りなしの問題を落としている／同じ数字ばかり付けている等） |
| **非承認** | 完了コードが記録に無い／他の人のコードと重複している |

- **「データを分析から外す」ことと「報酬を払わない」ことは別**にする。
  最後までやってくれた人には払う。
- 完了コードは持っているのに記録に無い人がいたら、送信が全部失敗した可能性がある。
  その場合、参加者の画面には「このコードと時刻を控えて問い合わせてください」と出ているので、
  問い合わせの有無と時刻を突き合わせて判断する。

**完走レコードの見方**（研究者側の作業）:

```bash
python3 experiment/tools/export_transfer_firestore.py --out /tmp/fs
# → /tmp/fs/transfer_wellbeing.csv の record_kind = "session" の行が完走レコード。
#   completion_code 列を、参加者が貼ったコードと突き合わせる。
#   phase 列で ①calib ②test ③comfort を見分ける。
```

## 掲載したあとに見ること

**最初の数十件が届いたとき（①だけ）**

```bash
python3 experiment/tools/export_transfer_firestore.py --out /tmp/fs
python3 experiment/tools/analyze_transfer.py --in /tmp/fs/transfer_trials.csv --out /tmp/fs/out
```

見るのは3つ。**異常が無ければ何もせず最後まで走らせる**（義務的な一時停止ではない）。

1. 打ち切りなしの問題（全部聞かせる／全部見せる）の正答率が十分高いか
2. 字ごとの曲線が、いちばん早い時点で低く・全長で高くなっているか（床と天井が取れているか）
3. 1人あたりの実所要が見込み（聴覚 約11.5分・視覚 約4〜5分）から大きくずれていないか
