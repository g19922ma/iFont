## 掲載する順番

```
   ① 較正フェーズ・聴覚（50人）  ┐ この2本は同時に出す
   ② 較正フェーズ・視覚（100人） ┘
            ↓ 両方とも集まりきったら、データを見て生成・凍結
            ↓ 参加者の会員IDを「回答不可リスト」に登録
   ③ 検証フェーズ（75人）  ┐ この2本は同時に出す
   ④ 群C（30人）          ┘
```

③④は①②が終わってからでないと出せない（①②のデータでアニメーションを作るため）。

**較正フェーズが2本に分かれているのは、聴覚（約12分）と視覚（約5分）で謝礼が違うから**である
（掲載1本につき金額は1つしか付けられない）。同じ人が両方に出ようとすると、
サーバの照合で自動的にお断り画面になる。

## 費用の計算式（見積もりを誤らないために）

```
1人あたり = （謝礼ポイント − 2）× 1.5円 ＋ 標準利用料 10円
総額       = 1人あたり × 人数 × 1.1（消費税）
```

例: 200ポイント × 100人 → (200−2)×1.5 + 10 = 307円 → ×100×1.1 = **33,770円**。

⚠ **「謝礼 × 1.3」では足りない。** 実費はおよそ **謝礼 × 1.5 ＋ 10円、さらに消費税**である。

**4本の合計 = 74,729円（税込）。予算枠7.5万円に対して余りは約270円しかない。**
人数を1人でも増やすと超えるので、増やすときは必ずこの式で計算し直すこと。

## ①② が終わったらすること（③④ を出す前に）

1. **参加者の会員IDを「回答不可リスト」に登録する。**
   ①②に参加した人の会員IDを、Yahoo!クラウドソーシングの回答不可リストに入れてから
   ③④を掲載する。サーバ側でも参加者IDで照合して断るが、**サイト側でも二重に塞いでおく**
   （サーバの照合は作業を始めてからしか効かないので、応募の段階で減らせるほうがよい）。
2. データを見て、アニメーションの生成と凍結を済ませる
   （`project/掲載文.md` 1.6 の手順）。
3. `experiment/transfer_config.js` の `visual.gates_ms` を聴覚と同じ字ごとの配置にそろえる
   （`project/掲載前チェックリスト.md` G-5）。**これをやらないと③を掲載してはいけない。**

## 承認・非承認の基準（4本とも共通）

| 判断 | 条件 |
|---|---|
| **承認** | 提出された完了コードが、サーバの**完走レコード**にある |
| **承認（ただしデータは分析から外す）** | 完走レコードはあるが、回答の質が低い（打ち切りなしの問題を落としている／同じ数字ばかり付けている等） |
| **非承認** | 完了コードが記録に無い／他の人のコードと重複している |

- **「データを分析から外す」ことと「報酬を払わない」ことは別**にする。
  最後までやってくれた人には払う。
- 完了コードは持っているのに記録に無い人がいたら、送信が全部失敗した可能性がある。
  その場合、参加者の画面には「このコードと時刻を控えて問い合わせてください」と出ているので、
  問い合わせの有無と時刻を突き合わせて判断する。

**完走レコードの見方**（研究者側の作業）:

```bash
python3 experiment/tools/export_transfer_firestore.py --out /tmp/fs
# → /tmp/fs/transfer_wellbeing.csv の record_kind = "session" の行が完走レコード。
#   completion_code 列を、参加者が貼ったコードと突き合わせる。
#   phase 列で ①②calib ③test ④comfort を見分ける（①と②は group 列で acal / aprime）。
```
