## 掲載する順番

```
   ① 較正フェーズ（253人・1本）
            ↓ 集まりきったら、データを見て生成・凍結
            ↓ 参加者の会員IDを「回答不可リスト」に登録
   ② 検証フェーズ（168人）  ┐ この2本は同時に出す
   ③ 群C（30人）           ┘
```

②③は①が終わってからでないと出せない（①のデータでアニメーションを作るため）。

**較正フェーズは1本の掲載**で、聴覚（群Acal・約7.5分）と視覚（群A′・約4.5分）へ
**サイト側が自動で振り分ける**（重み 80:150。23人で1巡するので253人配ると
ちょうど11巡し、内訳が正確に88人・165人になる）。参加者はどちらか一方だけを行う。

⚠ **2026-08-25 に2本から1本へまとめた。** 2本だと同じ人が両方に応募すること自体を
事前に防げなかった（サーバの照合で2つ目は断れるが、それは課題を開いた後になる）。
謝礼を一律にして金額を分ける必要をなくし、1本にした（この時点は100ポイント）。

⚠ **同日中に、謝礼をさらに一律100ポイント→25ポイントへ下げた。** 丸山が募集サイトに
出ている他のタスクの謝礼を確認したところ、25ポイントはむしろ相場より高いほうだった
（丸山決定・2026-08-25）。

較正フェーズとのあいだで単価の考え方が食い違っている。掲載前にこの2つも下げるか判断が要る。

| 項目 | 入れる値 |

> **「謝礼ポイント追加」で 2 を引くのはなぜか。** サイトの標準の謝礼が **2ポイント**で、
> そこに上乗せするぶんを入れる欄だからである。参加者が受け取るのは
> 「2 ＋ 追加ぶん」＝表の「謝礼ポイント」になる。
> **この2ポイントを含め、1ポイントが何円分にあたるかは掲載を作る画面で丸山が確認済み**
> ⚠ **参加者側の画面には「◯ポイント」としか出ず、円の併記は無い**
> （2026-08-25 に丸山が確認）。1ポイントが何円分かはこちらからは確かめられない。
> 時給換算は1ポイント＝1円分という前提で計算している。**実費には影響しない。**
> **下の費用の式は実費をポイント数から直接出すもの**なので、この確認結果は
> 予算の見積もりには影響しない。

回答欄は「6文字の完了コードを貼り付けてもらう」自由記述1つでよい。

⚠ **①はこの設定に合わせて、募集人数ぶんの設問ファイルを作ってアップロードする必要がある。**
作り方は `project/掲載文.md` 1.3b 節を参照。

## 費用の計算式（見積もりを誤らないために）

```
1人あたり = （謝礼ポイント − 2）× 1.5円 ＋ 標準利用料 10円
総額       = 1人あたり × 人数 × 1.1（消費税）
```

例: 200ポイント × 100人 → (200−2)×1.5 + 10 = 307円 → ×100×1.1 = **33,770円**。

⚠ **「謝礼 × 1.3」では足りない。** 実費はおよそ **謝礼 × 1.5 ＋ 10円、さらに消費税**である。

**3本の合計 = ~~74,729円~~ → ~~60,403円~~ → ~~65,848円~~ → ~~69,820円~~ → 38,511円
（税込・2026-08-25訂正。出典は上記と同じ）。**
予算枠7.5万円に対して余りは**36,489円**。人数を増やすときは必ずこの式で計算し直すこと。

（60,403円 → 65,848円 の差 5,445円は、較正フェーズを1本にまとめる際に
短いほう（視覚150人）の謝礼を70→100に上げたぶん。65,848円 → 69,820円 の差 3,972円は、
較正フェーズの募集人数を非承認に備えて230→253人に上積みしたぶんである。
69,820円 → 38,511円 の差 31,309円は、較正フェーズの謝礼を100ポイント→25ポイントに
下げたぶんである。）

## 承認・非承認の基準（3本とも共通）

| 判断 | 条件 |
|---|---|
| **承認** | 提出された完了コードが、サーバの**完走レコード**にある |
| **承認（ただしデータは分析から外す）** | 完走レコードはあるが、回答の質が低い（打ち切りなしの問題を落としている／同じ数字ばかり付けている等） |
| **非承認** | 完了コードが記録に無い／他の人のコードと重複している |

- **「データを分析から外す」ことと「報酬を払わない」ことは別**にする。
  最後までやってくれた人には払う。
- 完了コードは持っているのに記録に無い人がいたら、送信が全部失敗した可能性がある。
  その場合、参加者の画面には「このコードと時刻を控えて問い合わせてください」と出ているので、
  問い合わせの有無と時刻を突き合わせて判断する。

**完走レコードの見方**（研究者側の作業）:

```bash
python3 experiment/tools/export_transfer_firestore.py --out /tmp/fs
# → /tmp/fs/transfer_wellbeing.csv の record_kind = "session" の行が完走レコード。
#   completion_code 列を、参加者が貼ったコードと突き合わせる。
#   phase 列で ①calib ②test ③comfort を見分ける（①の中は group 列で acal / aprime）。
```
