## 1. 下見とは何か（なぜ16人だけ先に取るのか）

本番の実験は4つの参加者集団に分かれ、合計で数百人を募集する。その前に、**16人だけ**の
小さな回を1度はさむ。目的は次の4つで、どれも「本番を始めてしまうと直せない」ことである。

| 何を確かめるか | なぜ本番前でないと困るか |
|---|---|
| 打ち切りなし（音や文字を最後まで出す問題）で、ほぼ全員が正しく答えられるか | ここが低いと、録音そのものか画面の作りに問題があることになり、以降の測定が全部むだになる（計画書 4.4-7） |
| 基準アニメの長さ（文字が0%から100%まで現れきるのに何ミリ秒かけるか） | 速すぎると「薄くてもすぐ読める」ため正答率が狭い範囲で跳び、あとの計算（逆引き）が不安定になる（計画書 Q4）。今は暫定600ミリ秒 |
| 1人あたりの実際の所要時間 | 掲載文に書く分数と報酬額の根拠になる。長すぎれば問題数を削る |
| 打ち切る時刻の置きどころ（今は20・40・60・80・110・150・220ミリ秒の7点） | 正答率が動く時間帯からずれていると、曲線の形が測れない。下見のデータをシミュレーション（A2）に入れて確定する |
| 同じところまで見せたとき、そこへ**速く着いたか・ゆっくり着いたか**で正答率が変わるか（RQ4） | 本手法は「同じ進み具合なら正答率も同じ」を土台に組んである。下見で見るのは**当たり**だけで、本回答は本番の視覚較正で出す。ここでは「本番の人数で答えが出せる精度になるか」を見積もるためのデータを取る（計画書 3章 RQ4・10章⑦） |

下見の参加者は本番の4集団には入れない（同じ人が2度出ないようにするため。名簿で照合する）。

## 2. 掲載の設定値

| 項目 | 値 | 補足 |
|---|---|---|
| タイトル | **【約7分】音声・文字の聞き取り/見え方の簡単なテスト（研究用・スマホ可）** | ⚠ 分数は掲載前に自分で1回通して実測し、ずれていたら直す（→ チェックリスト F-4） |
| 募集人数 | **16人**（サイト側が自動で 音声8人 / 視覚8人 に振り分ける） | 応募者が半分ずつ2つの課題に分かれる。応募者は課題を選べない |
| 報酬 | **1人 200円** | 7分なら時給1,700円ほど、10分でも1,200円ほど。計画書11章の「時給1,000円目安」を下回らない |
| 応募条件 | 日本語が母語・18歳以上・**1人1回** | 年齢は同意画面でも明示する |
| 作業URL | `https://g19922ma.github.io/iFont/experiment/transfer_calib.html?prod=1&wid=<作業者ID>` | **音声の人も文字の人も同じ1本**。別々に掲載すると同じ人が両方に出るのを防げない（計画書 4.3） |
| 完了の確認 | 完了コード方式（12桁） | 最後の画面に出る英数字を、掲載側の回答欄に貼ってもらう |
| 募集期間 | 目安2日 | 16人が埋まり次第しめ切る |

> **URLについての注意**: `?prod=1` を落とすと、同意画面も完了コードも出ず、データも保存されない
> （研究者の動作確認モードになる）。`wid=` はクラウドソーシング側が作業者IDを差し込む書き方に
> 合わせる（サイトによって `wid` / `worker_id` / 置換タグの書式が違う）。差し込みができないサイトなら
> `?prod=1` だけでもよい。その場合は完了コードだけが本人確認の手がかりになる。

### 作業の内容

大学の研究のためのアンケート（テスト形式）です。**パソコンでもスマートフォンでも参加できます。**

ひらがな1文字が、**音声**または**画面上の文字**として、ごく短い時間だけ提示されます。
それを見て（聞いて）、どのひらがなだったと思うかを、五十音の表から1つ選んでください。
これを続けて100問ほど行います。1問は数秒です。

- 提示はとても短く、**はっきり分からないのがふつう**です。分からなくても、いちばん近いと思う文字を選んでください。正解・不正解で報酬が変わることはありません。
- 答える時間に制限はありません。落ち着いて選んでください。
- 開始時に、**音声の課題**と**文字の課題**のどちらかが自動的に割り当てられます（ご自身では選べません）。
- 所要時間はおよそ7分です。

### 参加できる方

- 日本語を母語とする、18歳以上の方
- お一人につき1回のみ（同じ方の2回目の回答は無効になります）

### ご用意いただくもの・環境

- **音声の課題になった場合**：音を出せる環境（スピーカーでもイヤホンでも構いません）と、**静かな場所**が必要です。開始前に音量を調節する画面があります。
- **文字の課題になった場合**：画面の明るさを普通以上にしてください。開始前に見え方を確認する画面があります。
- 途中でブラウザを閉じても、**同じ端末・同じブラウザで開き直せば続きから再開**できます。

### 作業の手順

1. 下記のURLを開きます。
2. 説明と同意の画面を読み、同意して進みます。
3. 音量（または見え方）の確認 → 進め方の説明 → 練習を1問以上 → 本番。
4. 最後の画面に**12桁の完了コード**が表示されます。
5. そのコードを、この募集の回答欄に貼り付けて提出してください。

**作業URL**：（ここに作業URLを貼る）

### 個人情報について

お名前・メールアドレスなど、個人を直接特定できる情報は記録しません。記録するのは、
各設問への回答とその所要時間、参加者を区別するための識別子、画面サイズなどの技術情報だけです。
データは研究目的にのみ使用し、統計的に処理したうえで研究発表等に用います。

### ご注意

- **完了コードが表示される画面まで到達しないと、報酬をお支払いできません。**途中でやめた場合は、お手数ですが未提出のままにしてください。
- 明らかに設問を読まずに同じ選択肢を押し続けているなど、回答として成立していない場合は非承認とすることがあります。
- ご不明な点は、この募集のメッセージ機能からお問い合わせください。

実施：津田塾大学 栗原研究室

## 4. 承認・非承認の目安（掲載側の作業）

| 判断 | 条件 |
|---|---|
| 承認 | 提出された完了コードが、記録側（`transfer_trials` シートの `completion_code` 列）にあり、最後まで到達している |
| 承認（データは分析から外す） | 最後まで到達しているが、打ち切りなしの問題（確認問題A）を落としている等、回答の質が低い |
| 非承認 | 完了コードが記録に無い／他の人のコードと重複している |

- **「データを分析から外す」ことと「報酬を払わない」ことは別**にする。最後までやってくれた人には払う。
  除外の線引きそのものは、下見のあとのシミュレーション（A2）で数値を固定する（計画書 7.3）。

## 5. 下見が終わったらすること

1. `transfer_trials` シートを取り出し、打ち切りなしの問題の正答率を字ごとに出す。
   低い字があれば、その字は**録り直す**（別の字に差し替えない。計画書 4.3 の選定規則）。
2. 1人あたりの実所要時間の中央値を出し、掲載文の分数と報酬を本番用に決め直す。
3. 視覚の回答から、基準アニメの長さ（今は暫定600ミリ秒）を決める。
4. **速さの効きめ（RQ4）の当たりを見る**。`transfer_trials` の `base_anim_ms` 列で
   群A′フェードの回答を2つに分け、同じ進み具合の水準での正答率を比べる。差は効果量と
   信頼区間で書く。**下見は予備なので「差がない」とは断定しない**（本回答は本番の
   視覚較正で出す）。あわせて、**本番の群A′の人数だと信頼区間がどのくらいの幅に
   なるか**を見積もる（計画書 3章 RQ4・10章⑦）。
5. **内挿の確認**。較正の提示水準を1つずつ伏せて曲線を当てはめ直し、伏せた水準の正答率を
   予測できるかを見る（追加データは要らない）。大きく外れる水準があれば、A2 で水準を
   足すか配置を変える（計画書 7.1）。
6. 1〜5をシミュレーション（A2）に入れて、打ち切り時刻・まぎれ字の量・必要人数を確定する。
7. 確定した数値を `experiment/transfer_config.js` に入れ、`config_version` を上げてから
   本番を掲載する。
   **`visual.calib_speed_probe` は切らない**——速さ2水準の測定は RQ4 の本回答を取るために
   本番の視覚較正でも続ける（下見のときだけの仕掛けではない）。
   生成に使う視覚の曲線は600ミリ秒の水準だけと事前に決めてあるので、
   2水準を測っていても生成の中身は左右されない（計画書 7.1）。
