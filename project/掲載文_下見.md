## 1. 下見とは何か（なぜ16人だけ先に取るのか）

本番の実験は5つの参加者集団に分かれ、合計で数百人を募集する
（較正の聴覚・較正の視覚・検証の聴覚・検証の視覚・見え心地）。その前に、**16人だけ**の
小さな回を1度はさむ。目的は次の4つで、どれも「本番を始めてしまうと直せない」ことである。

| 何を確かめるか | なぜ本番前でないと困るか |
|---|---|
| 打ち切りなし（音や文字を最後まで出す問題）で、ほぼ全員が正しく答えられるか | ここが低いと、録音そのものか画面の作りに問題があることになり、以降の測定が全部むだになる（計画書 4.4-7） |
| 基準アニメの長さ（文字が0%から100%まで現れきるのに何ミリ秒かけるか） | 速すぎると「薄くてもすぐ読める」ため正答率が狭い範囲で跳び、あとの計算（逆引き）が不安定になる（計画書 Q4）。今は暫定600ミリ秒 |
| 1人あたりの実際の所要時間 | 掲載文に書く分数と報酬額の根拠になる。長すぎれば問題数を削る |
| 打ち切る時刻の置きどころ（今は20・40・60・80・110・150・220ミリ秒の7点） | 正答率が動く時間帯からずれていると、曲線の形が測れない。下見のデータをシミュレーション（A2）に入れて確定する |
| 同じところまで見せたとき、そこへ**速く着いたか・ゆっくり着いたか**で正答率が変わるか（RQ4） | 本手法は「同じ進み具合なら正答率も同じ」を土台に組んである。下見で見るのは**当たり**だけで、本回答は本番の視覚較正で出す。ここでは「本番の人数で答えが出せる精度になるか」を見積もるためのデータを取る（計画書 3章 RQ4・10章⑦） |

下見の参加者は本番の5集団には入れない（同じ人が2度出ないようにするため。名簿で照合する）。

## 4. 承認・非承認の目安（掲載側の作業）

| 判断 | 条件 |
|---|---|
| 承認 | 提出された完了コードが、**完走レコード**（`transfer_wellbeing` の `record_kind = "session"` の行の `completion_code` 列）にある |
| 承認（データは分析から外す） | 完走レコードはあるが、打ち切りなしの問題（確認問題A）を落としている等、回答の質が低い |
| 非承認 | 完了コードが記録に無い／他の人のコードと重複している |

- **完走レコードは、最後の画面（完了コードが出る画面）に到達したときに1行だけ入る。**
  だから「最後まで到達したか」を1問1行の記録の行数から推測しなくてよい。
  同じ行に、答えた問題数（`n_trials`）・所要秒（`duration_s`）・
  **送信できなかった記録の件数**（`send_failures`）も入っている。
- `send_failures` が 0 でない人は、通信が悪くて1問1行の記録を取りこぼしている。
  **報酬は払う**（本人の落ち度ではない）。分析に足りるかは別に判断する。
- 完了コードが完走レコードに無いのに参加者がコードを持っている場合は、
  送信がすべて失敗した可能性がある。その場合、参加者の画面には
  「このコードと時刻を控えて問い合わせてください」という案内が出ているので、
  問い合わせの有無と時刻を突き合わせて判断する。

- **「データを分析から外す」ことと「報酬を払わない」ことは別**にする。最後までやってくれた人には払う。
  除外の線引きそのものは、下見のあとのシミュレーション（A2）で数値を固定する（計画書 7.3）。

## 5. 下見が終わったらすること

1. `transfer_trials` シートを取り出し、打ち切りなしの問題の正答率を字ごとに出す。
   低い字があれば、その字は**録り直す**（別の字に差し替えない。計画書 4.3 の選定規則）。
2. 1人あたりの実所要時間の中央値を出し、掲載文の分数と報酬を本番用に決め直す。
3. 視覚の回答から、基準アニメの長さ（今は暫定600ミリ秒）を決める。
4. **速さの効きめ（RQ4）の当たりを見る**。`transfer_trials` の `base_anim_ms` 列で
   群A′フェードの回答を2つに分け、同じ進み具合の水準での正答率を比べる。差は効果量と
   信頼区間で書く。**下見は予備なので「差がない」とは断定しない**（本回答は本番の
   視覚較正で出す）。あわせて、**本番の群A′の人数だと信頼区間がどのくらいの幅に
   なるか**を見積もる（計画書 3章 RQ4・10章⑦）。
5. **内挿の確認**。較正の提示水準を1つずつ伏せて曲線を当てはめ直し、伏せた水準の正答率を
   予測できるかを見る（追加データは要らない）。大きく外れる水準があれば、A2 で水準を
   足すか配置を変える（計画書 7.1）。
6. 1〜5をシミュレーション（A2）に入れて、打ち切り時刻・まぎれ字の量・必要人数を確定する。
7. 確定した数値を `experiment/transfer_config.js` に入れ、`config_version` を上げてから
   本番を掲載する。
   **`visual.calib_speed_probe` は切らない**——速さ2水準の測定は RQ4 の本回答を取るために
   本番の視覚較正でも続ける（下見のときだけの仕掛けではない）。
   生成に使う視覚の曲線は600ミリ秒の水準だけと事前に決めてあるので、
   2水準を測っていても生成の中身は左右されない（計画書 7.1）。

## 6.1 群Cとは何か（なぜ別の掲載にするのか）

もとは群B（アニメを見てかなを当てる集団）の課題の最後に、見え心地の質問をくっつけていた。
それを別の実験として切り出した。理由は3つある（計画書 4.5）。

1. 群Bは1人あたり90問以上の識別課題をこなす。その直後に「この表示は続けて見ていられるか」を
   聞くと、答えているのが表示の性質なのか、やり終えた疲れなのかを分けられない。
2. 独立させれば、同じアニメを**打ち切らずに何度でも流しつづける**形にできる。
   字幕は本来くりかえし流れるものなので、そのほうが実態に近い。
3. 群Bの負担が減る。

見せるのは **4つの現れ方 × 3通りの出し方 = 12本**である。出し方の3通りは
「1字だけ」「5字を左から並べて出た字は残す」「5字を同じ場所で入れ替える」で、
5字続けるときは**前の字が現れきってから0.3秒空けて**次が出る
（前後の字が互いの見え方を邪魔しない間隔。計画書 4.5）。

## 6.4 承認・非承認の目安（掲載側の作業）

| 判断 | 条件 |
|---|---|
| 承認 | 提出された完了コードが、**完走レコード**（`transfer_wellbeing` の `record_kind = "session"` の行の `completion_code` 列）にある |
| 承認（データは分析から外す） | 完走レコードはあるが、12本すべてに同じ数字を付けているなど、回答の質が低い |
| 非承認 | 完了コードが記録に無い／他の人のコードと重複している |

- `transfer_wellbeing` には**3種類の行**が入る。`record_kind` 列で見分ける。
  - `final` … 1参加者1行の本記録。**分析はこれを読む**（`wellbeing_json` に12本ぶん）
  - `clip` … 1本ごとの中間レコード（12行／人）。本記録が落ちたときの保険で、分析には使わない
  - `session` … 完走レコード。**承認の判定はこの行だけで済む**
- 群Cは1参加者1レコードなので、以前は本記録の送信が落ちると完了コードがどこにも
  残らなかった。いまは送信を待って再試行し、それでも駄目なら参加者の画面に
  「このコードと時刻を控えて問い合わせてください」と出す（2026-08-21 に修正）。

- 群Cには正誤が無いので、質の判定は「同じ数字ばかりを付けていないか」「1本あたりの所要が
  極端に短くないか」で行う。どちらも `wellbeing_json` の中に入っている
  （各本の `ratings` と `view_ms`）。線引きの数値はデータを見てから決める。
- **「データを分析から外す」ことと「報酬を払わない」ことは別**にする。最後までやってくれた人には払う。

## 6.5 群Cが終わったらすること

1. `transfer_wellbeing` の `phase` 列が `comfort` **かつ** `record_kind` 列が
   `final`（または空）の行を取り出す。`clip` と `session` の行は分析に使わない。
2. `wellbeing_json` を開いて、1本1行の表に開く
   （参加者ID・提示順 `order`・方式 `family`・出し方 `presentation`・出した字 `chars`・
   7件法3項目 `ratings`・流れた周の数 `cycles`・押して流し直した回数 `replays`・
   その本にかけた時間 `view_ms`・実際の表示幅 `char_px`）。
   最後の2問は `choice_family`（現れ方）と `choice_presentation`（出し方）に入っている。
3. 3項目のうち「目障り・わずらわしい」は**向きが逆**なので、集計の前に 8 から引いて反転する。
4. **方式ごと**と**出し方ごと**の平均を別々に出す。あわせて、方式と出し方の組合せで
   食い違いが出ていないか（ある方式は横並びだと評価が落ちる、など）も見る。
5. 提示順の効き目（先に出たものが有利／不利になっていないか）を確かめる。
6. 忠実さ（群Bの距離E）と見え心地を、横軸=忠実さ・縦軸=見え心地の図に置く（計画書 3章）。
   図に使う見え心地は**1字条件の値**にそろえる（群Bの識別課題が1字だけを見せているため）。
