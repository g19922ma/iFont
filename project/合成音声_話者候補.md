# 合成音声の話者候補（転写検証実験の刺激）

最終更新: 2026-08-21

## 1. 何をしたか・なぜか

転写検証実験の刺激を、人が読んだ自然音声から **VOICEVOX の合成音声**に切り替える。
理由は、この研究の最終的な応用が「合成音声を入力とするシステム」であり、
そのシステムを較正するデータも同じ音源で取ったほうが筋が通るため（ユーザー判断）。

自然音声の資産（`recordings_raw/`、`experiment/transfer_stimuli/`）は**捨てずに凍結**する。

その準備として、**声の候補を4人ぶん作り、清濁（か／が のような濁点の有無）が
区別できるかを機械で測って、聴き比べページにまとめた**。
最終的にどの声を使うかは、耳で聴いて人が決める。

## 2. 音の作り方（ここが要点）

**完全に無加工**である。VOICEVOX に1字だけ渡し、返ってきた合成の設定
（`audio_query` と呼ばれる、話速・音の高さ・抑揚・音量・前後の間などをまとめたもの）を
**1つも書き換えずに**そのまま合成へ回している。

やっていないこと（意図的に「やる口」をコードに作っていない）:

- 長さをそろえる
- 声の高さを平らにする
- 破裂から声までの時間（後述の VOT）を補正する
- 字ごとにフィルタを掛け分ける
- 文（文脈）の中から1字を切り出す

やっていること:

- **音量そろえのみ**。1音まるごとに一定の倍率を掛ける。いちばん小さい字の音量に合わせ、
  増幅はしない（倍率は 1.0 以下）。音の中身の強弱の配分は変えていない。

> **なぜここまで念を押すか**: 以前の刺激づくりでは合成音に手を加えた結果、
> 「ぽ」が濁って（「ぼ」に）聞こえる不具合が出た（`project/清濁診断_音響測定.md`）。
> 同じ轍を踏まないために、加工の入口を最初から作らない方針にした。

### 配信用の 100Hz ハイパスは掛けない（記録しておく決定）

自然音声では、電源から入る「ブーン」という低い雑音（電源ハム、50Hz または 60Hz）を
落とすために、**配信する音そのもの**に 100Hz より下を削るフィルタ（ハイパス）を掛けていた。

**合成音にはこの雑音がそもそも存在しないので、100Hz ハイパスは掛けない。**
音に触れる処理を1つ減らせるので、無加工の方針とも一致する。

なお、音の始まり（acoustic onset）を**検出するときだけ**掛ける 150Hz のハイパスは、
自然音声のときと同じく掛けている。これは検出用の一時的な処理で、書き出す音には残らない。

## 4. 清濁の手がかり（VOT）の実測値

### 用語

- **VOT**（voice onset time／破裂から声までの時間）… 唇や舌を離して「パッ」と
  破裂させた瞬間から、声帯が鳴り始めるまでの時間。単位はミリ秒。
  - **プラス**＝破裂したあとに声が始まる。息だけの区間があるということ。無声音（か・た・ぱ）の特徴。
  - **マイナス**＝破裂する前から声が鳴っている（「予備の声」がある）。有声音（が・だ・ば）の
    強い手がかり。日本語では「ば」「だ」「が」でよく起きる。
- **清濁の間の差** … 同じ口の形の清音と濁音で VOT を測り、その引き算
  （無声の VOT − 有声の VOT）。**プラスに大きいほど、時間の手がかりで清濁を区別できる**。
  0ms 前後だと、この手がかりでは区別できない（声の高さの出だしや破裂の強さなど、
  別の手がかりに頼ることになる）。

### 測り方

`experiment/tools/build_tts_candidates.py` が自動で測る。

1. **音の始まり（acoustic onset）**: 自然音声とまったく同じ規則。窓 5ms・刻み 1ms で
   短時間のエネルギーを出し、背景の雑音の水準より 10dB 高い状態が 10ms 続いた最初の点。
   検出には 150Hz のハイパスを掛ける。既存の
   `segment_natural_recording.detect_onset` をそのまま呼んでいる。
   （合成音の頭は事実上の無音なので、雑音の水準はこの関数の予備値 −80dBFS に落ちる。
   しきい値は −70dBFS。音のピークは −16dBFS 前後なので十分低い。）
2. **破裂の瞬間**: 1.5kHz より上の帯域の力が 3ms のあいだに急に立ち上がる点。
3. **声が出はじめる点**: 波形に周期があるかで判定する。まず 40ms の窓で大まかに探し、
   次にその区間の周期の長さを使って 1ms ずつさかのぼり、周期が崩れる点まで詰める。
4. **VOT** = 3 − 2。

## 5. 機械測定からの所見

**あくまで機械が測った時間の話であり、聞こえ方そのものではない。決めるのは耳。**

- **青山龍星（男性・低音）が、時間の手がかりでは最も強い。**
  が・だ・ば・ど・ぼ・び で「破裂の前から声が鳴っている」（VOT がマイナス）状態が
  はっきり出ており、清音との差が 20〜60ms ある。13 対のうち 11 対で差が 5ms 以上。
  弱いのは「ぷ／ぶ（±0）」「ぺ／べ（−9）」の2対。
- **No.7 が次点。** か／が の差が +85ms と極端に大きく、ぱ／ば +12ms、ぽ／ぼ +10ms と
  唇の音でも差がある。ただし「ご」の破裂が取れないなど、字ごとのばらつきは大きい。
- **東北きりたん（第一候補）と春日部つむぎは、時間の手がかりが弱い。**
  か行（か・き・く・こ）では差が +15〜+32ms あるが、**た行・ぱ行ではほぼ差がない**
  （た／だ ±0、ぱ／ば ±0〜+1、ぽ／ぼ −1〜±0）。
  つまり「ぱ」と「ば」、「た」と「だ」、「ぽ」と「ぼ」は、破裂から声までの時間では区別できない。
  区別できるとすれば、声の高さの出だしや破裂の強さといった別の手がかりによる。
- 上の点は、以前から出ていた「合成した1音で清濁が混同される」という問題
  （`project/相談_合成かな1音の清濁混同.md`、`project/清濁診断_音響測定.md`）と
  **符合している**。当時は加工が原因ではないかと疑っていたが、
  今回は無加工でも同じ傾向が出ているので、**話者そのものの性質**という可能性が高い。
- 「ぽ」が濁って聞こえた件について、東北きりたん・春日部つむぎでは
  ぽ（+3ms）と ぼ（+3〜+4ms）が数値上まったく同じで、混同が起きても不思議はない。
  青山龍星では ぽ +2ms / ぼ −34ms と明確に離れている。

### 選ぶときの推奨（機械測定からの示唆）

1. **清濁の区別を最優先するなら青山龍星。** 男性・低音なので声の印象は自然音声（女性話者）から
   大きく変わるが、実験の成否は清濁が聞き分けられるかに掛かっているので、
   まずこの声で「ぱ／ば」「た／だ」「ぽ／ぼ」を聴いてみる価値がある。
2. **女性の声を残したいなら No.7。** きりたん・つむぎより時間の手がかりが明らかに強い。
3. **東北きりたん・春日部つむぎを選ぶ場合は、た行・ぱ行の清濁が耳で区別できるかを
   念入りに確かめること。** 数値上は区別がつかないので、もし耳でも紛らわしければ、
   実験の結果が「知覚の限界」ではなく「刺激の欠陥」で決まってしまう。

> 注意: 上の VOT は自動測定であり、字によっては破裂や声の始まりを取り違えている可能性がある。
> 対ごとの差の絶対値を鵜呑みにせず、**話者どうしの大小関係を見る**のが正しい使い方。

ページの中身:

- **話者カード**（4人）… クレジット表記、清濁の差の中央値、
  「この話者で全68字を通して聴く」ボタン
- **清濁の対で聴く**… 1つのセルに清音と濁音を並べ、下に差を表示。
  「続けて」で4話者ぶん 清→濁 と続けて鳴る
- **要注意の字**… ぽ・ぴ・ぷ
- **全68字**… 行=かな × 列=話者。「横に聴く」で1字を4話者ぶん続けて鳴らす
- 下部の帯に、いま鳴っている字と話者・進捗（何字目／全体）・「止める」ボタン。Esc でも止まる

音はページに**埋め込んである**（再生用に MP3 128kbps モノラルへ変換したもの）ので、
1ファイルで完結し、どこで開いても鳴る。判断のもとになる音そのものは
`experiment/tts_candidates/<話者名>/<かな>.wav`（無加工の WAV・24kHz）。
ローカルで開いたときは、埋め込みが読めない場合に自動でこの WAV へ切り替わる。

## 8. ファイルと再現手順

| パス | 中身 |
|---|---|
| `experiment/tools/build_tts_candidates.py` | 合成（無加工）＋音量そろえ＋onset と VOT の測定 |
| `experiment/tools/build_tts_voice_compare.py` | 聴き比べページの生成（音を MP3 で埋め込む） |
| `experiment/tools/tts_voice_compare.html` | 聴き比べページ（生成物・リポジトリに入れる） |
| `experiment/tts_candidates/<話者名>/<かな>.wav` | 候補の音（**リポジトリに入れない**・`.gitignore` 済み） |
| `experiment/tts_candidates/measurements.json` | 全話者・全68字の測定値 |
| `experiment/tts_candidates/speakers.json` | 話者一覧とクレジット文言・規約文 |

再現:

```bash
# 1. VOICEVOX エンジンを起動しておく（既定 http://127.0.0.1:50021）
curl -s http://127.0.0.1:50021/version     # 動作確認（2026-08-21 時点は 0.25.2）

# 2. 合成と測定（4話者 × 68字でおよそ2分）
python3 experiment/tools/build_tts_candidates.py

# 3. 聴き比べページの生成（ffmpeg が必要）
python3 experiment/tools/build_tts_voice_compare.py
```

話者を変えるときは `--speakers 108,13,29,8` に別の ID を渡す。
ID は `curl -s http://127.0.0.1:50021/speakers` で一覧できる。
