# 子音と母音の時間の配り方: 現行プールと一様伸縮プールの比較

作成 2026-08-18。1文字の聴覚刺激を「1モーラ 0.2 秒」に固定するとき、その 0.2 秒を子音と母音に
どう配るかで 2 つのやり方がある。どちらを実験の本番プールにするかを決めるための材料である。

## まず聴き比べる

同じ話者・同じ音高・同じ音量処理で、**時間の配り方だけが違う** 68 音を 1 音ずつ聴けるページ。
かなのボタンを押すとその音が 1 回鳴る。「すべて順に再生」で五十音順に流すこともできる。

| どちら | URL |
|---|---|
| 現行(方式1: 子音長を保ち、母音で 0.2 秒に帳尻を合わせる) | https://g19922ma.github.io/iFont/experiment/pilot_soa_audio.html?check=1 |
| 試作(方式2: 子音と母音を同じ倍率で伸縮して 0.2 秒にする) | https://g19922ma.github.io/iFont/experiment/pilot_soa_audio.html?pool=uniform200&check=1 |

ページ上部の話者リンクからも行き来できる（方式2 は「候補: 一様伸縮200ms(方式2)」）。
**聴きどころは さ行・は行の 6 音（し・す・せ・さ・ひ・へ）** で、ここだけが 20 ミリ秒以上動く。
現行では母音が痩せて「シュッ」という摩擦だけが目立ち、母音の音色が確かめにくい。
方式2 では摩擦が短くなり母音が戻る。ほかの 62 音は 10.7 ミリ秒以内の差か、まったく同じである。

## 2 つの配り方

VOICEVOX は 1 文字を合成するとき、子音の長さと母音の長さを別々の値として返してくる。
その素の値（例: 「し」は子音 185.0 ミリ秒 + 母音 145.0 ミリ秒 = 330.0 ミリ秒）を、
1 モーラ 0.2 秒に押し込めるのが、ここでいう「配り方」である。

**方式1（現行の本番プール）— 子音長を保ち、母音で帳尻を合わせる**

子音の長さは素の値のまま残し、母音の長さを `0.2 秒 - 子音長` にする。子音が 0.16 秒を超えるときだけ
0.16 秒で頭打ちにする（母音を最低 40 ミリ秒は残すため）。
実装は `two_char_audio/build_2char_pool.py` の `set_mora`（81〜89 行目）。
もともとは競技かるたの「伸ばし・余韻」（母音だけを引き延ばす操作）のための配り方だった。

**方式2（試作プール uniform200）— 子音と母音を同じ倍率で伸縮する**

倍率 `k = 0.2 秒 ÷ (素の子音長 + 素の母音長)` を求め、子音長も母音長も k 倍する。
子音と母音の比が、エンジンが出した自然な比のまま保たれる。
PI（栗原氏）が動画生成ツール側で先に採り入れた規則と同じもので、
`ifont_tool/ifont/audio.py` の `synth_voicevox_slot(mode="uniform")`（コミット d4a5cf048）にあたる。
実験プール側の実装は `experiment/candidate_pools/uniform200/build_uniform200.py` の `set_mora_uniform`。

配り方以外は完全に同じである。話者（VOICEVOX 108 番・東北きりたん / ノーマル）、
音高（B3 = 246.94 Hz。合成後に実測し 50 セント以上ずれていたら 1 回だけ作り直す）、
VOT（破裂してから声が出るまでの間）の自動修正、ぱ行の字ごとの処方、
「ぽ」を「オッポ」の文脈から切り出す処方、A 特性（人の耳の感度）で重みづけした音量の均一化、
前後余白 0.1 秒、mp3 への変換（libmp3lame -q:a 4）、切り出し窓の作り方 — すべて現行と同一である。

## 数値の出どころ

表の子音長・母音長は **VOICEVOX に `/audio_query` で 1 字ずつ問い合わせて得た音素長を、
それぞれの方式で配り直し、エンジンの格子に丸めた値**である。mp3 の波形から測った値ではない。
単位はすべてミリ秒。

- エンジンは音素長を 1/93.75 秒 = 10.6667 ミリ秒の格子に量子化する。しかも子音と母音を
  別々に丸めるので、表の値はこの格子の倍数になり、モーラの合計も 0.2 秒ちょうどにはならず
  192.0 ミリ秒（18 格子）と 202.67 ミリ秒（19 格子）に割れる。これは現行プールでも同じで、
  方式2 で新しく生じる問題ではない（現行は 192.0 が 12 音・202.67 が 55 音・200.0 が 1 音、
  方式2 は 192.0 が 9 音・202.67 が 58 音・200.0 が 1 音）。
- 波形と食い違ってはいない。`experiment/tools/build_gate_windows.py` が、この配り方から
  予測される合成 WAV の長さと、実際の mp3 を復号した長さが 68 音すべてで一致することを
  確かめている（一致しなければそこで処理を止める）。方式2 のビルドでもこの検算は通っている。
- 「子音の差」「母音の差」は **方式2 − 方式1**。プラスは方式2 のほうが長いという意味。

再現手順（VOICEVOX を 127.0.0.1:50021 で起動しておく）:

## 要点

**1. 動くのは 68 音中 30 音だけ。うち母音の長さが動くのは 23 音（21 音が伸び、2 音が縮む）。**
母音だけのモーラ（あ・い・う・え・お・ん）と、素のモーラ長がもともと 0.2 秒に近い音は、
両方式でまったく同じ値になる。「ぽ」は文脈合成から切り出す処方なので配り方の規則を通らず、
2 つのプールで同一の音声である。

**2. 差が大きい上位 5 音はすべて摩擦音である。**

| 順 | かな | 母音長 方式1 → 方式2 | 子音長 方式1 → 方式2 |
|---|---|---|---|
| 1 | し | 42.7 → 85.3（**2.0 倍**） | 160.0 → 117.3 |
| 2 | せ | 64.0 → 106.7（1.7 倍） | 128.0 → 96.0 |
| 3 | ひ | 74.7 → 96.0（1.3 倍） | 128.0 → 96.0 |
| 4 | さ | 85.3 → 117.3（1.4 倍） | 106.7 → 85.3 |
| 5 | す | 53.3 → 85.3（1.6 倍） | 138.7 → 117.3 |

（3〜5 位は「子音の差 + 母音の差」の合計で並べているため、母音の伸び幅の順とは少し違う。
母音の伸び幅だけで並べると し・せ（+42.7）、さ・す（+32.0）、ち・ひ・へ（+21.3）の順になる。）

**3. 「し」の母音は 42.7 ミリ秒から 85.3 ミリ秒へ、ちょうど 2 倍になる。**
現行プールで最も母音が痩せていた音である。素の合成では子音 185.0 + 母音 145.0 = 330.0 ミリ秒あり、
0.2 秒に収めるのに 130 ミリ秒削る必要がある。方式1 はこれを母音からだけ削るので、
子音長が上限の 160 ミリ秒に張り付き、母音は残り 42.7 ミリ秒しか残らない
（モーラの 79% が子音）。方式2 は両方を 0.606 倍にするので、子音 117.3・母音 85.3 になる
（モーラの 58% が子音。素の比は 56%）。

**4. 摩擦音・破擦音ごとの変化。**

| かな | 種類 | 母音長 方式1 → 方式2 | 変化 |
|---|---|---|---|
| し | 歯茎硬口蓋摩擦音 [ɕ] | 42.7 → 85.3 | **+42.7**（最大） |
| せ | 歯茎摩擦音 [s] | 64.0 → 106.7 | **+42.7**（最大） |
| さ | 歯茎摩擦音 [s] | 85.3 → 117.3 | +32.0 |
| す | 歯茎摩擦音 [s] | 53.3 → 85.3 | +32.0 |
| そ | 歯茎摩擦音 [s] | 96.0 → 106.7 | +10.7 |
| ち | 歯茎硬口蓋破擦音 [tɕ] | 106.7 → 128.0 | +21.3 |
| ひ | 硬口蓋摩擦音 [ç] | 74.7 → 96.0 | +21.3 |
| へ | 声門摩擦音 [h] | 96.0 → 117.3 | +21.3 |
| は | 声門摩擦音 [h] | 106.7 → 117.3 | +10.7 |
| ほ | 声門摩擦音 [h] | 117.3 → 128.0 | +10.7 |
| ふ | 両唇摩擦音 [ɸ] | 96.0 → 106.7 | +10.7 |
| **つ** | 歯茎破擦音 [ts] | 117.3 → 117.3 | **変化なし** |

「つ」は素のモーラ長が 203.6 ミリ秒とほぼ 0.2 秒なので、どちらの方式でも縮める量がほとんどなく、
配分が一致する。摩擦音・破擦音だからといって必ず動くわけではない、ということである。

**5. 母音が縮む音が 2 つある（ろ・る）。**
「ろ」は 192.0 → 181.3、「る」は 181.3 → 170.7 で、いずれも 10.7 ミリ秒（格子 1 つぶん）の減少。
素のモーラ長がそれぞれ 141.4・148.1 ミリ秒と 0.2 秒より短いので、この 2 音は縮めるのではなく
**引き伸ばす**側にあたる。方式1 は伸ばしぶんを母音だけに乗せるが、方式2 は子音にも配るため、
そのぶん母音が短くなる。ら行のはじき音 [ɾ] は素の子音が 11〜28 ミリ秒しかないので、
体感できるほどの差ではないと思われるが、記録として残す。

**6. モーラ全体に占める子音の割合。** 子音を持つ 61 音の平均で、
素の合成が 19.4%、方式1 が 23.6%、方式2 が 20.9%。方式2 のほうが素の比に近い。
なお PI が文章の読み上げで測ったとき（コミット d4a5cf048 のメッセージ）は
素 27.6% → 方式1 16.6% → 方式2 24.9% と、方式1 が**下**に外れていた。孤立モーラでは逆に
方式1 が**上**に外れる。単語や文の中のモーラは 0.2 秒より短いことが多く、
方式1 では伸ばしぶんが母音だけに乗って子音の割合が下がるのに対し、
孤立モーラは 68 音中 37 音が 0.2 秒より長く、方式1 では削りぶんが母音だけから引かれて
子音の割合が上がるためである。**外れる向きは逆だが、素の比から遠いのはどちらも方式1** である。

**7. VOT 修正の収束先が 1 音だけ変わった。**
無声破裂音の VOT（破裂してから声が出るまでの間）が 25 ミリ秒に届かない音は、
子音長を 1.0 → 2.0 → 2.5 → 3.0 倍と順に試して最初に届いた倍率を採る、という手順を
両方式で同じように回している。方式1 では「て」が 2.5 倍で届いたが、方式2 では届かず 3.0 倍まで
進んだ。方式2 では倍率を掛けたあとに全体を縮めるので、同じ倍率でも実際の子音長が短くなるためである。
結果としての子音長・母音長は 42.7 / 160.0 ミリ秒で両方式とも同じになった（表の「て」の行）。
ほかの 7 音（く・け・た・と・ぴ・ぷ・ぺ）は方式1 と同じ倍率に収束した。

**8. 実際に鳴る長さ（切り出し窓）。**
再生時は、音響的な立ち上がり（レベルが −63 dBFS を 15 ミリ秒以上超え続ける最初の点）から
モーラの末尾までを鳴らす。この長さは現行が 149.0〜204.7 ミリ秒、方式2 が 159.0〜204.7 ミリ秒。
現行で最短だった「ふ」が 149.0 → 164.7 ミリ秒に伸び、最短は「へ」の 159.0 ミリ秒に替わって、
音ごとのばらつきが少し小さくなった。
音量をそろえる増幅率は現行が 0.910〜1.168 倍、方式2 が 0.925〜1.048 倍で、どちらも中央値 1.00。

## 作り方（再現手順）

VOICEVOX 0.25.2 を 127.0.0.1:50021 で起動し、numpy と praat-parselmouth の入った環境
（`~/ifont_env`）で上から順に実行する。

