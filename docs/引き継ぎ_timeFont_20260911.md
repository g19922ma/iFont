## 2. timeFont とは何か（30秒で）

音声を途中まで聞くと、最後まで聞く前に「何の文字か」が分かり始めます。
文字アニメーションも、途中まで見せると同じことが起きます。

この2つを、**同じ「当てられた割合」でつなぐ**のが timeFont です。

```
音声を 60 ms 聞いた時点で 81% の人が「ま」と分かる
                    ↓ 同じ 81% になる文字の状態を探す
文字アニメーションを進行度 65% まで進めた状態
```

そのために、両方の「途中まで見せたときの正答率」を実際に測りました。
測った対応表を持っておけば、任意の文字列に適用できます。

## 3. データの地図

### 3.1 3つの実験

| 実験 | 何を測ったか | 人数 | 実施日 | 生データ |
|---|---|---|---|---|
| **較正（聴覚）** | 音声を途中で切って聞かせ、何の文字か答えてもらう | 90名 | 8/25 | `data/raw/calib1_聴覚と視覚_1回目/` |
| **較正（視覚）** | 文字アニメーションを途中で止めて見せ、何の文字か答えてもらう | 325名（8/25 に163名、8/27 に162名） | 8/25・8/27 | `data/raw/calib2_視覚_2回目/` |
| **一対比較** | 生成した2つの表示を並べて、自然さと好ましさを選んでもらう | 111名 | 8/30 | `data/raw/pair_一対比較/` |

**この3つに重複して参加した人はいません。** 応募の時点で過去の参加履歴を照合し、
すでに参加していた人は対象外にしています。

### 3.2 ⚠ calib2 は calib1 を含んでいます

ここが一番間違えやすいところです。

- `calib1_聴覚と視覚_1回目/` … **8/25 の時点で書き出したもの**
- `calib2_視覚_2回目/` … **8/27 までの全部**（聴覚90 + 視覚325 = 415名）

`calib2` の方が新しく、`calib1` の中身を**全部含みます**（participant_id が252名分そのまま重なります）。
`transfer_trials.csv` の `phase` 列で見分けられます。`calib` が1回目、`calib2` が2回目です。
**分析には `calib2` を使ってください。** `calib1` は 8/25 時点での集計結果を残すために置いてあります。

視覚を2回に分けたのは、1回目のあとで**ぼかし解除方式とワイプ方式の提示水準を変えた**ためです。
1回目と2回目で参加者は重なりません。生成に使う曲線は、2回分の水準を合わせて求めています。

### 3.2.1 ⚠ 人数は名簿ではなく試行データで数えます

`transfer_roster.csv`（名簿）と `transfer_trials.csv`（試行）で人数が違います。

| 数え方 | 聴覚 | 視覚 |
|---|---|---|
| 名簿 `transfer_roster.csv` | 89 | 326 |
| **試行 `transfer_trials.csv`（論文の数字）** | **90** | **325** |

名簿には「割り当てたが一度も課題を開かなかった人」が含まれ、
逆に回答した人が名簿に載っていない場合もあります。
**論文の「聴覚90名・視覚325名」は試行データ側の数です。**

```python
# 正しい数え方
rs = [r for r in csv.DictReader(open("transfer_trials.csv", encoding="utf-8-sig"))
      if str(r.get("is_test")).upper() != "TRUE"]
# phase=calib  & group=acal    → 聴覚 90 名
# phase=calib  & group=aprime  → 視覚 1 回目 163 名
# phase=calib2 & group=aprime  → 視覚 2 回目 162 名
```

### 3.3 一対比較のデータの形

`wellbeing_comfort.jsonl` がすべてです（ファイル名が comfort なのは、
前身の実験のコレクション名をそのまま使ったため。中身は一対比較です）。

1行が1レコードで、`record_kind` が3種類あります。

- `clip` … 1回の比較（これが本体。2,749行、テストを除くと2,677行）
- `session` … セッションの記録
- `final` … 完走の記録

比較の中身は `wellbeing_json` の中に入っています。

```json
{"kind": "pair", "vary": "family", "ch": "が",
 "left": "reveal", "leftCond": "c3_acc_mid",
 "right": "blur",  "rightCond": "c3_acc_mid",
 "order": 24, "scores": {"natural": 1, "prefer": 1},
 "cycles": 1, "replays": 0, "view_ms": 1559}
```

**`scores` の値は -1 が左（A）、+1 が右（B）です。** 1/2 ではありません。
`experiment/transfer_pair.js` の1186行目に `[["-1", "Aの方が" + w], ["1", "Bの方が" + w]]` とあります。
ここを読み違えると、結果が**そっくり逆になります**（実際に一度間違えました）。

### 3.4 方式と条件の記号

| 記号 | 論文での呼び方 | 中身 |
|---|---|---|
| `fade` / うすい | フェード | 文字全体を薄い状態から濃くする |
| `reveal` / 点ふえ | 部分表示 | 画素を無作為な順に加える |
| `blur` / ぼかし | ぼかし解除 | 強いぼかしを弱める |
| `wipe` / 端から | ワイプ | 左から右へ描画領域を広げる |

| 記号 | 論文での呼び方 | 中身 |
|---|---|---|
| `c1_acc_shape` | 正答率（各時点） | 各時点の正答率を一致させる |
| `c2_info_shape` | 情報量（各時点） | 各時点の情報量を一致させる |
| `c3_acc_mid` | 正答率（中点） | 正答率が中点に達する時刻だけ合わせ、あとは等速 |
| `c4_info_mid` | 情報量（中点） | 情報量が中点に達する時刻だけ合わせ、あとは等速 |

「中点」とは、その量が測定された最小値と最大値のちょうど中間に達する最初の時刻です。

「情報量」は、回答の散らばりから求めた KL ダイバージェンスです。
回答した文字を R、提示した文字を c、提示水準を j として、
`P(R | c, j)` が `P(R | j)` からどれだけ離れているかをビット単位で測ります。
正答に至らない回答でも、特定の文字に偏っていればこの値は大きくなります。

## 4. 列の意味（生データ）

### 4.1 較正データ `transfer_trials.csv`（1行 = 1試行）

主なものだけ挙げます。

| 列 | 意味 |
|---|---|
| `participant_id` | 参加者の記号。**`worker_id` も同じ値**が入っています（Yahoo のIDではありません） |
| `group` | `acal` = 聴覚、`aprime` = 視覚 |
| `target_char` / `response_char` | 出した文字 / 答えた文字 |
| `correct` | 正解したか |
| `modality` | `audio` / `visual` |
| `family` | 表示方式（fade / reveal / blur / wipe） |
| `gate_ms` | 音声を何 ms で打ち切ったか |
| `progress_pct` | 文字アニメーションを何 % まで進めたか |
| `is_filler` / `is_decoy` / `is_catch` / `check_kind` | 本命でない試行の印。**分析では `check_kind` が空のものだけを使います** |
| `ua` | ブラウザの情報。**除外の判定に使うので消さないでください**（次項） |
| `base_anim_ms` | アニメーション全体の提示時間（300 / 500 ms） |
| `rt_ms` | 反応時間 |
| `is_test` | 動作確認の行。**必ず除きます** |

### 4.2 ⚠ ぼかし解除は WebKit 端末を必ず除きます

**iOS の全ブラウザと macOS Safari では、canvas の `ctx.filter = blur(...)` が効きません。**
ぼかし方式の刺激が一切ぼけず、鮮明な字がそのまま出ていました。

判定は `ua` を見て行います（`scripts/analyze_calib2.py` の56〜64行目）。

```python
webkit = ua.contains("iPhone|iPad|iPod") | (ua.contains("Macintosh") & ua.contains("Safari")
                                            & ~ua.contains("Chrome|Chromium|Edg/|Firefox"))
```

該当したのは45名（13.8%）で、**ぼかし解除の分析からのみ**除いています。
他の3方式には影響しません。`ua` を消すとこの除外が再現できなくなります。

### 4.3 参加者の除外

確認問題で判定しています。`承認判定_calib2.csv` にその結果があります。

- **full確認問題**（打ち切らずに全部見せる6問）の正答率
- **進行度20%以上**（見えやすい水準）での正答率
- 反応時間の中央値

2回目の163名では、非推奨になったのは4名でした（未実施1、未完走2、でたらめ回答の疑い1）。
論文では「聴覚1名、視覚6名を除外」と書いています。

### 5.1 ⚠ `analyze_pair.py` は 2026-09-11 に書き直したものです

**一対比較の分析コードは、実験当時のものが残っていませんでした。**

| | 結果 |
|---|---|

## 8. 落とし穴（実際にはまったもの）

1. **`scores` は -1 / +1。** 1 を左と読むと結果が逆になります（3.3節）。
2. **`calib2` は `calib1` を含む累積。** 足し算してはいけません（3.2節）。
3. **ぼかし解除は WebKit を除く。** `ua` を消さないでください（4.2節）。
4. **`check_kind` が空の試行だけが本命。** フィラーやおとりが混ざっています。
5. **`is_test` は必ず除く。** 動作確認の行が混ざっています。
6. **一対比較の分析コードは書き直したもの。** 尺度値に微差があります（5.1節）。
7. **`ts` はミリ秒。** 秒だと思うと1970年になります。
8. **人数は名簿ではなく試行データで数える。** 名簿だと聴覚89・視覚326になり、論文と1名ずつずれます（3.2.1節）。

## 9. 公開するときの注意

このフォルダは**共同研究者の間で使う前提**です。外部に出すときは次を確認してください。

- `worker_id` は、このデータでは participant_id と同じ匿名の記号です（Yahoo のIDではありません）。
  ただし **Yahoo に納品した TSV には Yahoo 側のワーカー番号が入っています**。
  そちらは共有していません（手元にのみ置いてあります）。
- `ua`（ブラウザの情報）は端末の特定につながる可能性があります。
  分析に必要なので残していますが、公開時はブラウザ名だけに短縮することを勧めます。
- 参加者の自由記述（`aware_text` 列など）は読み返していません。公開前に確認してください。
